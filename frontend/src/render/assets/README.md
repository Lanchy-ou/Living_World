# Viewer art assets

All art used by the replay viewer lives in this directory as TypeScript source. There are no
image files and no third-party assets. The normative description is
`docs/spec/frontend-design-v0.1.md` §3 (asset interface); this file is the asset record.

## Asset record

| File | Contents | How it was made | Source / author | License |
|---|---|---|---|---|
| `pixels.ts` | Sprite primitives (RGBA buffers, mirror, rotate, recolour, display hash) | Written for this project | Living Island project (task P2-F1) | Same as the repository |
| `residentArt.ts` | Resident sprites, 16x20: three hair designs, three views, three frames; corpse sprite derived from them | Hand-authored character grids, written for this project | Living Island project (task P2-F1) | Same as the repository |
| `objectArt.ts` | Fruit, fruit piles, canteen, tree fruit, action bubbles | Hand-authored character grids, written for this project | Living Island project (task P2-F1) | Same as the repository |
| `terrainArt.ts` | Trees, fruit tree, rocks, cave, spring, damp moss, grass tufts and flowers | Small deterministic generator functions and character grids, written for this project | Living Island project (task P2-F1) | Same as the repository |
| `index.ts` | Sprite lookup by key (no art) | Written for this project | Living Island project (task P2-F1) | Same as the repository |

The ground textures and the coastline are generated by `../terrainLayer.ts` from the replay's
map. They are code, not assets.

The owner's concept image ("A — Warm Pixel Art") was used as a style reference only. No pixels
were copied from it and it is not in the repository.

## Third-party assets

None. Before adding one:

1. get the owner's approval in chat (task card rule);
2. check that the license allows redistribution in this repository;
3. add a row to `art/LICENSES.md` (source URL, author, license) **and** a row to the table
   above, in the same commit as the asset.

## Conventions (summary)

- One character per pixel in a grid of equal-length strings; `.` is transparent; every other
  character must be in the sprite's palette. `spriteFromRows` throws on a ragged row or an
  unknown character, and the tests build every sprite.
- Tile art is drawn for 16x16 source pixels per tile. Tall sprites are anchored to the bottom
  of their tile and overlap the tile above.
- Residents are 16x20 with views `down`, `up`, `right` (`left` is the mirror) and frames
  `idle`, `walk_a`, `walk_b`. A resident's look depends only on its index in the bundle's
  resident list.
- Sprite keys: `resident/<index>/<facing>/<frame>`, `corpse/<index>`, `item/<name>`,
  `emote/<name>`. Terrain decoration keys are internal to `terrainArt.ts`.
- Variation (tree shapes, tufts, wave marks) uses the deterministic `hash01` of tile or pixel
  coordinates. `Math.random` is never used.
- To add a sprite: add the grid or generator here, give it a key in `index.ts` if the scene
  draws it, and add or update its row in the table above.
