## 0. Purpose

P3 was closed on 2026-11-16 as a delivered foundation, with long-duration proof
and the full M10 matrix deferred, not passed
([P3 closeout](../tasks/p3/P3-closeout.md)). P3.5 builds on that foundation,
including P3-06 (multi-resident) and P3-07 (inspection artifact). It builds
fuller, extensible versions of the two core systems:

- the world as a data-driven rule system (materials with properties, generic
  verbs, transformations as content);
- the resident agent built around memory (one working context per waking
  period, built from long-term memory and the day's experience, and long-term
  memory maintained by consolidation while the resident is unconscious).

Acceptance targets the preconditions for emergence: information spreads and is
believed or doubted; rules are discovered, remembered and taught; artifacts persist
and are used by others; commitments hold across days.

The rule discovery layer (C) is not a P3.5 system. It is a design constraint on
systems 1 and 2 and becomes its own phase after the rule system (B) runs.

## 3. Known dependencies

- System 1 comes first: every other system depends on it, and it changes a frozen
  contract (change-request process, §7).
- System 1 and system 2 are designed together: the protocol shape depends on how
  rules are represented.
- System 5 can start early, except "learned skills", which depends on system 2.
- System 7's action form is fixed by system 1.
- System 4 is content only: the engine never contains code for one recipe.

### 4.1 Acceptance runs (M15)

- **[Owner]** 5 LLM residents, 7 game days, two arms (memory on, memory off),
  3 seeds per arm: 6 runs, 210 resident-days. Five residents allow information
  chains longer than two hops.
- **[Owner]** Acceptance is by occurrence and traceability, not by rate
  thresholds. Each of the four capabilities (ADR 0014 D2) must occur in the
  acceptance runs, and every counted instance must trace to its sources in the
  logs (for example, each hop of an information chain to the utterance that
  carried it). No rate threshold is set in P3.5, because no measured base rate
  exists yet; the minimum occurrence counts are spec values in
  `evaluation-v0.1.md`.
- **[Owner]** The memory on/off difference is reported in the metrics; memory
  off is defined in ADR 0014 D2. If no difference is seen, the report says so
  and gives a diagnosis (memories never recalled, a world too simple to need
  them, or prior knowledge that was enough), and the owner decides at Gate 3.
  This replaces the earlier wording that the difference must be visible.
- **[Owner]** Before the paid runs, a fake-model run with 5 residents over 7
  game days exercises the whole data path without provider calls: growing
  contexts, pending consolidation, recorded calls, replay and inspection
  artifacts. It is a P3.5 workload check, not a restart of the deferred P3
  proof (§10).
- Rough cost, from offline P3 measurements before the per-action loop: about
  CNY 4 per resident-day without cache discounts, so about CNY 900 for the
  matrix. M14 measures the real figure before M15 starts. Cost is monitored,
  not capped (ADR 0012 D4).

## 6. Handoff

Each task appends what changed, commands/results, deviations, open questions and
seven fields: base_commit/result_commit; status; scope_changed; human_interventions;
rework_rounds; verification (including NOT_RUN); open_questions. Unknown is explicit.

## 7. Change requests

A contradiction with a frozen specification is reported with current rule,
requested rule, impact, options and one recommendation in
`docs/spec/open-questions.md`. Stop only the affected work until owner
disposition. Downstream workers do not edit frozen specs. The first P3.5 change
request covers the frozen world–agent protocol (ADR 0007 D8). The order is:
the change request is filed, the owner decides it, ADR 0007 is accepted, and
then its successor spec is written and frozen. Both approvals are part of M11.

## 8. Naming rules

1. One fixed subject slug per system, used in ADR, spec and task names.
2. ADR: `docs/adr/NNNN-<slug>.md`, no version, no phase. A later reversal is a new
   ADR that names the one it supersedes.
3. Spec: `docs/spec/<slug>-vX.Y.md`. A new subject starts at `v0.1`; a new version
   is a new file and the old one is not edited. No "v2" in file names.
4. Phase appears only in plans and tasks: `docs/plans/p3.5-…`, `docs/tasks/p3.5/`.
5. Task IDs: `P3.5-<system code>-<NN>`, for example `P3.5-PR-01`; branch
   `task/P3.5-PR-01-<slug>`. The dot keeps them apart from P3-05 sub-task IDs such
   as `P305-R1`.

## 9. Exploration lane

Decided in ADR 0014 D4: `explore/<slug>` branches, runs under `runs/explore/`,
notes in `docs/explore/<slug>.md`, no Gate 2, no changes to frozen contracts or
specs, and promotion through a normal task before anything reaches `main`.
