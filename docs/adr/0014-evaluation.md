## Context

Memory and rule discovery cannot be iterated blind: for any decision we need to
see which memories entered the context, where they came from, what the model
answered and what the world did. P3-07 already plans a read-only inspection
artifact generated by the backend and imported by the frontend, separate from
`ReplayBundle` (`p3-evaluation-v0.1.md`). Acceptance for P3.5 is about the
preconditions for emergence, not about a story.

## Decision

### D1. Dashboard

- **[Owner]** The dashboard is an analysis mode inside the existing frontend,
  reusing the map replay, generated types and loading. A decision can jump to
  its moment on the map.
- **[Owner]** The first version reads finished runs only. Live viewing is later.
- Metrics and inspection data are computed by the backend (`analysis`) and
  written as read-only artifacts. The frontend only displays them; it computes
  no game logic and no metric.

Views:

| View | Shows |
|---|---|
| Decision inspector | The turn reason, context sections with sources, the model request and response, the world result, and the memories written afterwards |
| Memory browser | A resident's memories by kind, supersession chains, `needs_review` records, personality over time |
| Emergence metrics | The four capabilities (D2), with drill-down to instances |
| Comparison | Two runs side by side, for example memory on and off |
| Cost | Calls, tokens, cache hit rate, latency and fallback rate per resident and day; token share per context section (instructions, schema, current state, day log, recalled memories), from the context manifest (ADR 0013 D10); context size, context pressure and day-log growth per turn over the day, guard events, and fallback rate against context size (ADR 0013 D4, D8) |
| Rules and attempts | Rule use, and where unmatched attempts cluster |
| Time use | **[Owner]** The share of each resident-day spent on survival, exploring, crafting and talking (ADR 0010 D3) |

### D2. Emergence metrics

**[Owner]** Direction accepted; exact definitions go in the spec.

| Capability | Measured as |
|---|---|
| Information spreads | Claim chains from an utterance through listeners' told memories and retellings: hop count, and whether each listener believed it (high confidence or acted on it) or doubted it |
| Rules are discovered and taught | Residents' skill hypotheses compared with the true rules: coverage per rule, accuracy, and how each was first reached (below) |
| Artifacts persist and are used | Artifacts used as instrument or input by a resident other than the maker |
| Commitments hold across days | Agreements with structured terms (ADR 0007 D10) spanning at least one sleep, and whether each was kept, broken or expired, judged from objective events (transfers, positions, contributions and their ticks), never from what residents say |

**[Owner]** The model may know a recipe before it lives on the island, so
evaluation records how each resident first succeeded with a rule:

- right on the first attempt, with no related experience in its context, which
  may be prior knowledge;
- after its own failed attempts;
- after watching another resident's attempt, as its own perception delivered
  it (ADR 0007 D10);
- after being told by another resident;
- with a memory from an earlier day in its context.

Every path but the first counts as learned on the island. The strongest
evidence is a rule that goes against common sense (ADR 0010 D2).

**[Owner]** A skill hypothesis is scored by whether its predictions match the
actual outcomes on the items it was applied to. It is not scored by mapping a
descriptor such as "looks strong" to a band of true values, because a
deceptive material would make that mapping judge a correct lesson as wrong.
Hidden values never enter resident memory.

Memory on/off comparisons run several seeds per arm, because model output varies
between runs. Derived chance rolls (ADR 0009 D1) give both arms the same luck
for the same events, which reduces the number of seeds needed. **[Owner]** The
M15 acceptance runs use 5 residents, 7 game days and 3 seeds per arm, and are
judged by occurrence and traceability, not by rate thresholds
([P3.5 plan](../plans/p3.5-implementation-plan-v0.1.md) §4.1). Cost is measured
in full even though P3.5 sets no limit (ADR 0012 D4).

**[Owner]** Memory off removes memory across waking periods only. Both arms
share one period boundary: a waking period ends when the resident has been
unconscious for K ticks (ADR 0012 D2), whether or not a consolidation call
runs, and a shorter nap ends no period in either arm. The world runs the same
in both arms; the boundary acts on the agent side only. In the off arm:

- the new period starts with no earlier day log, no intention, no dialogue
  state, no long-term memories in the prefix, and recall that returns nothing;
- the resident keeps its identity, its base personality (no drift), its body
  and inventory, and what it perceives now;
- hard facts (ADR 0012 D1) are still written for evaluation but never shown to
  the resident;
- explored terrain stays, as in the on arm, because it is world-delivered
  static map data, not memory (ADR 0007 D4). This is the only stated
  exception.

The boundary is recorded with the run, so replay applies it the same way. A
synthetic test checks it: before a sleep, a resident holds a distinctive
intention, an unfinished dialogue and explored terrain now out of sight; after
waking, the off-arm context holds neither the intention nor the dialogue, the
terrain appears only as world-delivered map data, and position, inventory and
visible surroundings are intact.

**[Owner]** Arm comparisons use evidence that both arms produce: utterances,
attempts, actions and their outcomes in the objective log. Measures that need
consolidated records, such as told memories and skill hypotheses, are reported
for the on arm only and marked not applicable in the off arm.

**[Owner]** The on/off difference measures the whole cross-period memory
system, mechanical records included, not the consolidation model alone.
Narrower claims need consolidation diagnostics or a later targeted ablation.
Both arms use the same pressure policy (ADR 0013 D4). Morning memories can
start the on arm's day at higher pressure and lead to earlier sleep; that is
part of the measured effect. The report shows, per arm, prefix tokens,
pressure at waking, its growth, sleep timing and guard events. Neither arm is
padded or trimmed to make them equal.

**[Owner]** "No difference observed" is a valid result. If the two arms do not
differ, the report says so and gives a diagnosis, for example memories that
were never recalled, a world too simple to need them, or prior knowledge that
was enough.

**[Owner]** A memory in a context shows only that the resident could see it.
To test whether it changed a choice, evaluation runs counterfactual probes on a
few key turns: the recorded context of that turn with one memory removed is
sent to the model several times, and the choices are compared with those made
with the memory present. Probes are new model calls, recorded in a separate
experiment record; they never enter a run or its replay. Their design is Q6.

**[Owner]** Removing a memory also shortens the context, which can lower the
pressure cue (ADR 0013 D4). A probe is therefore labelled by what it holds
fixed: either it keeps the recorded cue and every other recorded input, or it
rebuilds the whole request, so the cue and the guard follow the change. The two
answer different questions and are reported separately, with the manifests
before and after.

Actions made by the fallback policy (ADR 0013 D7) never count as discovered,
taught or acted-on: metrics read the policy tag in the objective log and skip
them.

**[Owner]** Two experimental questions are evaluated, not assumed (exact
measures are Q5):

- Does a growing working context change behaviour observably (repeated actions,
  missed information, invalid output and fallback), and how does that relate to
  context size, time awake, the fatigue band and the context-pressure cue?
  (ADR 0013 D4, ADR 0012 D3)
- Does consolidation improve continuity across days (commitments kept, beliefs
  and skills carried over), form knowledge, and still forget what does not
  matter? (ADR 0012 D2)

**[Owner]** Context pressure, the mental fatigue band and sleep choices are
recorded at every turn, together with the exact cue text and any guard event,
so evaluation can separate how each cue affects decisions (Q5). Turns where the
guard left content out (ADR 0013 D4) are reported apart and never counted as
natural long-context effects.

Long-context effects depend on the model, so the model ID is an experimental
condition: runs with different models are not comparisons of the same
residents. **[Owner]** The pressure cue policy (counter, bands and wording) is
an experimental condition in the same way, and results are reported as
obtained under it.

### D3. Extension points as acceptance tests

Each extension point has a synthetic test proving that an addition needs only
registration or content, not engine or assembler code:

- a test memory kind is stored, consolidated and assembled into context;
- a test rule pack is settled by the engine, and the validator rejects a rule
  that breaks conservation;
- a test recall recipe is selected by its turn reason.

**[Owner]** The rule-pack test is M12 evidence; the memory-kind and
recall-recipe tests are M14 evidence; all pass before M15 (plan §4).

## Consequences

- The frontend grows an analysis mode, still read-only.
- Every metric needs objective-log and memory provenance good enough to trace a
  claim or a skill back to its source; this constrains ADRs 0007 and 0011.
- Exploration is faster, at the cost of a promotion step before anything lands.

| Q1 | Exact metric definitions, for example what counts as "acted on" a belief, and which actions count as survival, exploring, crafting or talking. |
| Q2 | The minimum occurrence count of each capability for M15 acceptance. |
| Q3 | Inspection artifact size limits and sharding for long runs with many residents. |
| Q4 | P3.5 drops the P3 trial caps (ADR 0012 D4). Do exploration runs still need a trial registration (for reproducibility only), or none? |
