# ADR 0004: P2 design

- Status: proposed (becomes accepted at M5)
- Date: 2026-11-10
- Task: P2-00 (specs: `docs/spec/rule-policy-v0.1.md`, `docs/spec/p2-experiments-v0.1.md`;
  plan: `docs/plans/p2-implementation-plan-v0.1.md`; change request: CR-004 in
  `docs/spec/open-questions.md`)

## Context

P2 ("Residents Survive") needs a deterministic rule-based resident that survives seven days
on the default island using only its own perception. It also needs measured evidence on
scarcity behaviour and the canteen. P1 provides the runtime, policy and save interfaces, the
world-owned exploration footprint and complete run artifacts. This ADR records the P2
decisions and the alternatives the owner's plan rejected.

## Decisions

- **Rule policy `rule-based-v0`:**
  - It is an ordered first-match rule list: reply, drink, fill, eat, seek water, sleep,
    gather, canteen pick-up and delivery, explore, idle. Need bands come from
    `OwnCondition`.
  - Targets are scored by unit-cost BFS distance over the explored footprint. Exact ties are
    broken by the `random-v0` hash construction with named domains. No world RNG is used.
  - A small typed `policy_state` holds the commitment, issued-intent references, failed
    targets, cue impressions and a canteen capacity learned by a bounded fill probe.
  - Back-off uses a disjoint action-by-failure-code matrix. A backed-off key blocks every rule
    that would target it, including reply transfers.
- **Private-state boundary (PD-06):**
  - Inputs are the `DecisionContext`, `PolicyConfig` with `rule_params`, and the policy's own
    state.
  - There is no private map memory: map knowledge comes from `explored_static_tiles`, and
    stock evidence only from the current packet.
  - Cue impressions are captured at decisions only, by owner decision (OQ-056). A cue seen
    only at a non-decision boundary is intentionally lost. There is no ingest hook, and the
    S5 contrast is scoped accordingly (rule-policy §7.4).
- **CR-004:**
  - Add `rule-based-v0` to `PolicyId`.
  - Add a typed `policy_state` validator.
  - Add an optional `PolicyConfig.rule_params`, omitted when null, so P1 bytes are unchanged.
  - Fix the CLI combinations.
  - Establish rule identity on restore from verified provenance (`rule_lineage`) across the
    continuation ancestry. The root tick-zero checkpoint is then mandatory, and restores are
    refused under RJ-1 to RJ-8.
  - The interface contract and the generated frontend types do not change.
- **Experiments (PD-05, PD-07):**
  - Scenarios: S1 spring visible (spawns only), S2 blind default, S3 `regrow_ticks = 288`,
    and S4 canteen enabled vs. restricted at decay 100 and then 120. S5 compares cue use
    enabled vs. ignored.
  - Disjoint development and acceptance seed lists of 20, generated by a stated hash
    procedure.
  - Metrics come only from `events.jsonl`, `decisions.jsonl`, checkpoints and `replay.json`
    (exported for every run). The technical gate checks trace, checkpoint and replay
    agreement and the canteen, slot, stock and conservation invariants.
  - PD-05: at least 15 of 20 acceptance seeds with all three alive at tick 1008, reported
    with a Wilson interval, after technical validity.
- **Experiment identity:** `run_id` behaviour is kept (OQ-049). Each case has an
  experiment-case ID, its own output directory and a manifest. The manifest holds the
  canonical `PolicyConfig` hash, separate from the world config hash.
- **Analysis:** a pure `living_island.analysis` module under a new forbidden-import contract.
  Loading lives in `scripts/p2_experiments.py`. The long matrix stays outside default CI.

## Rejected alternatives

- **Diversity quota.** There is no required fraction of behaviourally different seeds.
  Behavioural variation is a reported diagnostic. Event-log hashes differ by seed through
  the config hash alone, so they cannot show different behaviour (plan §1.1).
- **A 9-of-12 survival threshold.** It was replaced by PD-05's 15 of 20 on a held-out list
  with an interval. The smaller set gives a wider interval and weaker evidence.
- **Private map memory.** The world already owns the exploration footprint (WR §2), so a
  policy-side map would duplicate it and invite leaks. Historical tree-stock tracking is
  deferred too.
- **A true no-canteen arm.** It needs an experimental fixture with an invariant exception
  (BN §5 item 3), as does a map without the cue. P2 keeps both invariants and compares
  policy restrictions, labelled as such (plan §1.3 item 8).
- Also rejected: a separate `policy.json` for rule parameters, and a runtime ingest hook for
  cue capture (CR-004).

## Consequences

- No spec changes before M5. After M5, P2-00 applies exactly the CR-004 text to
  `agent-interface-v0.1.md` (marked `[CR-004]`) and sets this ADR to accepted.
- P2-01 wires the ID, validator, rule parameters and CLI. P2-02 implements the rules and
  creates the S1 and S3 scenario files. P2-03 builds the batch tool and analysis.
- The open questions OQ-054 to OQ-069 carry the assumptions for the owner's M5
  disposition. OQ-056 is already decided by the owner.
