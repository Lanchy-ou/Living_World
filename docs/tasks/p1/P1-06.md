### Findings

- **MINOR R-01 (M2 evidence).** In the default random run all three residents die at ticks
  222, 222 and 271. The demo's continuation from tick 432 therefore replays only an all-dead
  world with no decisions. It shows that resume works, but not resume with living residents.
  AI-08 and my 144-tick resume cover that case. Suggestion: note this in the handoff, or have
  the M2 demo resume from `checkpoint-0000000144.json`, so the owner's Gate 3 check sees live
  decisions after the checkpoint.
- **MINOR R-02.** `open_resume_output` publishes the staged directory without a final
  checkpoint, then reassigns the writers' private `_path`. Only the P1-05 storage tests use
  it, and it bypasses the OQ-048 rule that a continuation is published only after its final
  checkpoint. Suggestion: give the writers a public retarget method, or restrict the helper
  to tests, in P1-07 or later.
- **MINOR R-03.** A failed fresh `run` or `reexecute` leaves a partial output directory: logs
  and possibly checkpoints, with no manifest. Because of it, the same `--out` is refused
  until the user deletes the directory by hand. The error does not name the directory, as
  resume's staging note does. This is acceptable under "manifest only after success", but it
  is worth a diagnostic note.

Note for the owner, not a finding: `--seed` keeps the configured `meta.run_id`
(`default_island_seed20261108_run01`), so runs with different seeds share one run ID. The
config hash still tells them apart. If run IDs should reflect the seed, that needs its own
open question.

Open questions OQ-047 and OQ-048 are reasonable, reversible assumptions and still need owner
decisions.
