### Measurements

Windows 11 build 22000, Intel Core i7-12700H (14 cores, 20 logical processors), and
CPython 3.13.5. The backend script used one sequential sample per command with
`perf_counter` around the entire CLI subprocess, including `uv` startup and output IO.
Run and re-execution included replay export. Resume measures the 864 newly executed ticks
after checkpoint 144 and its counts are the written suffix.

| Operation | Elapsed | Events written | Decisions written | Replay bytes |

| Fresh random run, 1,008 ticks | 37.201 s | 3,654 | 439 | 2,645,806 |
| Resume, tick 144 to tick 1,008 | 15.633 s | 1,332 | 144 | — |
| Recorded re-execution, 1,008 ticks | 38.704 s | 3,654 | 439 | 2,645,806 |
| Browser load, median of 5 | 155.7 ms | — | — | 2,645,806 input |
| Browser seek from tick 0 to 1,008, median of 5 | 49.6 ms | — | — | — |

The browser sample used Chrome 156.0.8078.81 in headless mode with GPU disabled and a
1,280 × 900 window, serving the README's Vite dev server on loopback. Chrome DevTools
Protocol set the real file on the viewer's file input. `performance.now()` timed the
file-input change to the tick-0 UI with max tick 1,008 and two animation frames. The
seek sample timed the last-tick button click to tick 1,008 and two animation frames.
Each trial used a fresh page in the same browser session. One warm-up was excluded.
Load samples ranged from 143.3 to 163.4 ms and seek samples from 47.1 to 50.1 ms.
