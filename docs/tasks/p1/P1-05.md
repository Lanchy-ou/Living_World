## Handoff

### What changed

- Added read-only event sequence validation for world-allocated IDs, tick and sequence
  order, payload types and causal references. Added canonical append-only JSONL readers
  and writers for events and decisions, with typed file, field and line diagnostics.
- Added atomic checkpoint creation and validation against retained config and map identities.
  G2-R2-01 is covered by persisted-file tests for both an excessive decision ordinal and
  ingestion at the recorded death tick.
- Added retained config and map IO, script and trace identity verification, and isolated
  actor-local input slices. Trace manifests check log bytes and counts and carry the final
  world hash for the P1-06 re-execution comparison.
- Added continuation output with origin metadata and checkpoint-seeded log writers. The
  resume tests cover causal references into the source prefix, ignoring later source
  bytes, chained resume, and preservation of source file bytes and mtimes.
- Added 53 regression cases, including a Hypothesis test that checks byte-identical
  write/read/write for events, decisions, saves and manifests across 25 generated examples.

### Findings

- **G2-01 MINOR — `backend/src/living_island/persistence/_files.py:26`.** `atomic_create`
  serializes publishers with an exclusive `.<name>.lock` sidecar that is only removed in
  `finally`. After an abrupt termination the sidecar stays, and every later save to that target
  is refused with a bare `[Errno 17] File exists`, which does not say that the file is a stale
  lock. The same sidecar makes a resume output directory non-empty. Probe: pre-creating
  `.save.json.lock` made `write_checkpoint` raise `PersistenceError`. The handoff already
  discloses the sidecar. Name the lock in the error message, or document the manual cleanup.
- **G2-02 MINOR — `_files.py:28` and `:35-37`.** The existence check and `os.replace` are
  separate steps. A writer that does not take the lock can create the target in between, and on
  POSIX `os.replace` would overwrite it. Cooperating persistence writers are safe, and the
  brief names `os.replace`, so this is a hardening note only. A link-then-unlink publish is
  race-free, and no directory fsync follows the replace.
- **G2-03 MINOR — `backend/src/living_island/persistence/resume.py:116-135`.** Resume verifies
  the source event prefix against `event_cursor` but never reads the source `decisions.jsonl`.
  The saved `decision_record_cursor` and per-actor ordinals are not cross-checked against it.
  Probe: deleting the source `decisions.jsonl` still let `open_resume_output` succeed. The brief
  does not require the check, and P1-06 may own it. Record the owner of this check.
- **G2-04 MINOR — `resume.py:120-138`.** The output directory is created and `resume-origin.json`,
  `config.json`, `map.txt` and `script.json` are written before the log writers open. A failure
  part-way leaves a non-empty directory that the guard then refuses on retry. Code read only;
  not probed.
- **G2-05 MINOR — `backend/src/living_island/persistence/_codec.py:106`.** `digest(raw)` is a
  byte-level SHA-256 helper for file identities (script, trace, checkpoint). Config and map
  hashes still come from `world/content.py`, which has no byte digest, so this is not a second
  content hash. Note it as the one added helper next to the "no second hash" rule.
