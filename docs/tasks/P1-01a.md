### Findings

Paths beginning `world/`, `agents/`, `contract/` and `persistence/` are relative to
`backend/src/living_island/`.

- **G2-01 BLOCKER — `contract/save.py:62`, `backend/tests/unit/test_save_and_ports.py:63`.**
  The positive fixture passes with Ella alive and no pending packet. The validator checks
  sorting but accepts missing packets, wrong boundary ticks and mismatched actor sets.
  Interface Contract (IC) §5 and Agent Interface (AI) §6 require a resumable, pre-ingest
  checkpoint. Validate one exact packet per living actor, none for dead actors, and matching
  runtime/delivery actor sets and cursors. Use a valid positive fixture. File-version refusal
  and external-input checks are assigned to P1-05/P1-06.
- **G2-02 MAJOR — `world/content.py:87`.** With otherwise-default content,
  `needs.min_value = false` and `needs.min_value = 0.0` both validate and become integer
  `0`. World Rules (WR) §1.1 and IC §6.2 require a strict integer with value zero.
  Use a strict integer bounded to zero and test both TOML inputs.
- **G2-03 MAJOR — `world/protocol.py:253`.** A statement accepts explicit `request: null`
  and serializes an ordinary statement with both optional keys set to null. IC §2.4
  permits those keys only on the corresponding speech acts and specifies non-null values
  when present. Validate key presence and serialize absent keys as absent, including in
  nested plans and decision records. Test canonical round trips for all four acts.
- **G2-04 MAJOR — `world/ports.py:127`.** Assigning
  `acc.receipt_baseline[0].resident_id = "altered"` succeeds. The copied tuple exposes
  mutable receipt models and lists. Plan §2.1 requires an immutable tick-start baseline
  for novelty comparison. Expose immutable receipt data or keep a private deep copy and
  return isolated views.
- **G2-05 MAJOR — `world/facts.py:80`, `:93`, `:109`.** Five action payloads narrow
  IC §3.2's string `action_type` to `ActionType`; `action_failed.failure_code` is also
  narrowed to `FailureCode` (OQ-007). Conversely, a `resident_moved` JSON payload using
  `from_` instead of `from` validates. Restore the declared string types or approve the
  narrowing through §7, and accept only `from` on the wire.
- **G2-06 MAJOR — `world/protocol.py:329`.** A mismatched target/parameter model is
  rejected during `ActionIntent` construction. AI §3.1 and AI-03 require that result
  for policy plans (`INVALID_PLAN`), while IC §4 describes a bounded world failure
  for invalid parameter shapes. The same constructor guards both boundaries and no
  separate input path is declared. Resolve which shapes can reach world settlement
  under plan §7 before freezing the contract.
- **G2-07 MAJOR — `agents/types.py:107`, `:138`.** A tick-zero request at ordinal 1
  accepts empty triggers, and a P1 decision record accepts `llm_call_id="future-call"`.
  AI §2.2 reserves empty triggers for the initial tick-zero request, and AI §5 keeps
  P1 call IDs null. Validate these at the P1 request/record boundary and cover them
  with negative cases.
- **G2-08 MINOR — `world/facts.py:331`.** A JSON-shaped envelope with `type=[]`
  raises `TypeError` in the payload dispatch instead of reporting an invalid
  `EventType` (IC §3.1 and P1-05's clear-validation requirement). Check the type
  before catalog lookup.
- **G2-09 MINOR — `world/ports.py:193`.** `append_fact` takes `Sequence[str]`, wider
  than the array declared in plan §2.1. Use `list[str]` to match the other array
  annotations or specify the broader accepted input in the frozen signature.
- **G2-10 MINOR — `docs/spec/interface-contract-v0.1.md:137`.** A1 points to
  nonexistent §2.6 and says every policy emits an `ActionPlan`. AI §2.2 defines a
  `DecisionOutcome` with ok, error and replayed variants. Point to §2.4a and name
  the actual return type.
- **G2-11 MINOR — `persistence/content.py:22`, `world/content.py:273`.** The loader
  rejects parent-relative map paths and duplicate resident spawn tiles. Plan §2.1
  requires a relative map reference, and WR §1.1–§1.2 requires unique marker positions
  and passable spawns. Neither explicitly sets these two stricter policies.
  Remove the added restrictions or log them for owner disposition under plan §7.
