## Findings

### B1 (blocking): fallback filtering removes running controls and the neutral end signal

`backend/src/living_island/sim/v2/compat/policy_host.py:195`,
`PolicyHost.model_packet`. The filter sets a fallback-origin
`running_action` to null and removes its `progress_step` and
`action_ended` reports wholesale. Decision loop §§2.4 and 8.3 preserve
the running state, progress, continue/replace controls and a neutral
action-ended signal, while filtering origin-specific feedback and outcome
recipe keys. The runner still takes its turn from the raw packet, so the
model can be asked for a choice without the information needed to select
`continue`. Both modes reproduced this after restoring a six-tick rest:
the world kept its original active intent through a scripted `continue`,
and both model and memory callbacks saw `running_action=None`. A completed
fallback gather also lost its sole action-ended signal.

Keep neutral controls and scheduling metadata at the sim-to-model boundary.
Carry the durable intent and origin binding privately to suppress feedback,
outcome-specific recall and memory evidence, including a delayed stop after
model handback. Use typed neutral metadata if a `BoundaryDelivery` report
cannot represent the sanitized signal. Add the real-rest restore probe
`test_fallback_controls_after_restore` and
`test_fallback_end_signal_and_no_private_feedback` in both modes. They
should pass alongside `test_wap25_model_fallback_model_after_restore`,
with the raw packet, model request and memory input checked independently.

### B2 (blocking): the private v1 interrupt can dispatch a model turn

`backend/src/living_island/sim/v2/compat/policy_host.py:162` and
`:427`, `PolicyHost.ingest` and `PolicySession._deliver`. A private
interrupt decision is OR'ed into the model receiver's notification flag.
During an in-flight fallback move, an intermediate cue upgrade forces a
model request even when the model delivery callback declined the
notification. In `test_legacy_only_interrupt_does_not_override_model_mute`,
Ella's expected model ticks are 0 and 1. Both modes call again at tick 2,
while the action is running and there is no wake or end report. Decision
loop §§2.1–2.3 give the model a turn on an eligible report, with the
specified mute and critical-need rules. In the unmuted handback
probe, the model legally continues the move to success, but the policy
checkpoint records `interrupted/NEW_SIGHT` for that action.

Use the private interrupt for stand-alone policy scheduling. In a model
session, schedule from the model notification decision and ordinary
runner reasons. Keep legacy trigger bits available if a scheduled turn
actually uses fallback. Delay committing any synthetic interruption and
discarding the associated legacy queue until a replacement is selected
and committed. Add the muted cue probe and both branches of
`test_model_handback_resolves_real_stop_only`. Under continue, the
world and private state must agree. Under replacement, the confirmed
stop must be filtered across restore, as it is today. Keep WAP-30 and
the stand-alone Round 3 cue cases green in both modes.

### B3 (blocking): the bridge writes feedback into a typed v1 Perception

`backend/src/living_island/sim/v2/compat/policy_host.py:231`,
`PolicyHost._decision`. The frozen WAP §11.2 and the card limit bridge
output to policy-private state and decision records and forbid entry into
a `Perception`. The function first builds a clean projection, then
copies the bridge feedback into `v1.Perception.last_action_feedback`
and calls `Runtime.ingest` with a typed `v1.BoundaryPerceptionDelivery`.
The v2 journal, model, day-log and recall inputs remain clean in the
tested path. The temporary v1 object still conflicts with the literal
frozen boundary. The same wrapper carries the fabricated
`PLAN_FINISHED`, although CR-P3.5-PR-06 describes a request-only marker.

The frozen planner reads `request.context.perception.last_action_feedback`
(`agents/rule_based/policy.py:299`), so simply removing the assignment
breaks the archived back-off. Keep a clean public projection and put the
marker in the private request path. If the existing v1 types and runtime
must carry the feedback or marker, record that exact private exception as
a proposed change request and handoff deviation under runbook §6.1.
Recommend a single adapter-owned, non-published legacy planner input as
the temporary exception, with explicit limits on its ownership and
lifetime. Escalate any required v1 module change to the orchestrator.
Verify with a recording planner/runtime in a real gather failure:
`test_private_feedback_carrier_and_native_schedule_marker` observes
the two fields at the legacy runtime input today. Recheck the approved
private handoff and assert that neither field reaches any public packet
or consumer callback, while the archived policy back-off still passes.

### B4 (blocking): a cue can mask a real entity exposure in the shared engine

`backend/src/living_island/world/v2/engine/perception.py:163`,
`:211` and `:270`, `observe_step`, `expose` and
`build_perception`. The new path stores synthetic cue sightings under a
real entity's possible dictionary key. It also drops a genuine visible
entity from the receipt set when its ID is in the cue map. The v2 setup
boundary admits a cue with the same name as a placed tree
(`engine/validate.py:149` only checks cue uniqueness within cues and
positions). A same-named cue and tree can both appear in a generated
packet while the tree has no reference receipt, contrary to WAP §§3.3
and 5.3. The independent probe reproduces this with `fruit_01`.
The v1 config loader already prevents this overlap in pinned profiles.
The shared v2 engine now silently loses a valid receipt for an admitted
configuration.

Track last cue steps independently of `ctx.transient_sightings`, keep
the highest cue detail independently, and exclude only synthetic cue
records from entity-reference receipts. If a global namespace is
required by the intended engine contract, enforce it at setup admission
and cover that refusal. Add `test_world_setup_accepts_same_named_cue_and_entity`
or the explicit admission test and a transient-vector control. The
existing night vector must still deliver step 6 and leave cue-only IDs
out of reference receipts.
