## Findings

### B1 (blocking) — a checkpoint can publish or load a foreign packet prefix

[checkpoint.py:50–75](../../../backend/src/living_island/persistence/v2/checkpoint.py#L50),
`save_checkpoint`, `load_checkpoint` and `_check_prefix`, and
[journal.py:80–93](../../../backend/src/living_island/persistence/v2/journal.py#L80),
`PacketJournal.check_prefix`. Engine §2 ties committed journal content to the
run, resident and delivery ID. The checkpoint verifies the run label on the
journal object and file existence. It accepts a prefix directory containing
another run's real `0.json`; the journal's own `read(0)` rejects it. The same
prefix check accepts malformed bytes as long as the file exists.

Use the journal's validated batch reader, or an equivalent verified immutable
prefix, at the checkpoint boundary. Before publication or restore, enforce
the canonical run/tick identity of each referenced batch. Retain the
sim-owned cursor as opaque state. The scratch test
`test_checkpoint_refuses_foreign_batch_under_same_run_journal[save/load]`
fails on both paths and must pass with the fix. Keep the genuine journal as
the positive control and include a malformed batch case.

### B2 (blocking) — a future approval can become active at the current boundary

[tick.py:290–298 and 319–335](../../../backend/src/living_island/world/v2/engine/tick.py#L290),
`World.step` and `prepare_rules`, and
[rule.py:456–471](../../../backend/src/living_island/world/v2/rules/rule.py#L456),
`normalize_rule`. Rule representation §5.9 keeps proposals inactive until
approved. Engine §§3 and 13 admit already-approved additions in phase 1 of
opening boundary `t`, with the event labeled `t+1`. The loader verifies the
shape of `approved_at_tick`, but a proposal claiming approval at tick 8 can
enter the active library and emit its event from boundary 0 through
`record_boundary`.

At the boundary that admits rules, reject approval ticks greater than
opening `t` before storing a rule or changing the world. Apply the same
causal check when replay admits a recorded rule. Keep loader validation
independent of world time. `test_future_approval_cannot_commit_rule_at_zero`
fails today and should pass on refusal with the same full snapshot, pending
packets and library, and no published rule file. Add a control for approval
at the current boundary and a replay row whose stored provenance claims
future approval.

### B3 (blocking) — the manifest can attest to a parent absent from the composition

[manifest.py:30–55](../../../backend/src/living_island/persistence/v2/manifest.py#L30),
`RunManifest.capture` and `check_content`. The leaf carries its immediate
parent's ID. Matching that ID does not show that the effective leaf was
composed with the supplied parent's content. In the scratch test
`test_manifest_refuses_loaded_parent_inconsistent_with_loaded_leaf`, the
original leaf inherits six inventory slots. A separately loaded parent with
the same ID has seven. The actual leaf reloaded against the seven-slot
parent has a different hash, yet capture accepts the seven-slot parent
paired with the original leaf. `check_content` can then bless the same
contradictory pair by reconstructing those pins. A second control sets the
ancestor's stamina gain limit to zero. The leaf restores the limit with an
allowed replacement and loads to the original effective hash. The ancestor
fails standalone validation with `NEED_RATE`, so requiring every separately
loaded ancestor would also exclude this valid leaf (RR §5.10).

Derive pins from the actual loader composition or bind every supplied
ancestor to the ancestry of that composition. Keep the frozen §5.10
effective-content hash semantics. The scratch test must refuse capture of
the mixed pair and accept a coherent pair. Cover a changed ancestor on
manifest checking as well. The OQ can choose a representation without
limiting compositions that the loader already admits.

### B4 (blocking) — a published packet can mutate the authoritative world

[tick.py:277–278](../../../backend/src/living_island/world/v2/engine/tick.py#L277),
`World.pending_packets`. The outer tuple exposes the same DTOs held in
`state.pending_deliveries`. Nested lists remain mutable under Pydantic's
frozen model. Clearing a returned packet's `perception.visible_tiles`
changes the world's full snapshot bytes. Subsequent journal ingestion
would record the altered packet. This bypasses the world-owned immutable
delivery required by engine §2 and protocol §5.3.

Return detached packet values or an immutable view at this new public
boundary. Preserve their exact encoded bytes. The scratch test
`test_pending_packet_accessor_cannot_mutate_world` fails today and should
pass after the fix. Assert that journal bytes and acknowledgement still
match the original packet after the caller's mutation attempt.

### B5 (blocking, small) — the initialization event is appended with a placeholder hash

[tick.py:693–738](../../../backend/src/living_island/world/v2/engine/tick.py#L693),
`initialize`. The inherited bootstrap writes `world_initialized` with an
empty hash through `EventWriter.emit`, then replaces the appended event
after building the initial deliveries. EN-07 gives this field the authoritative snapshot
hash. An observer at the append sees different event bytes from the returned
log, the same publication concern resolved in EN-06. The final returned
event currently has the right hash.

Reserve the initialization event's tick-zero position and cursor contribution
while staging bootstrap, then materialize its final event once the snapshot
hash is known. Keep sequence zero, subsequent event IDs and the final
state's cursor. The scratch `test_initial_event_is_complete_when_appended`
captures the first event at the writer append and fails on different bytes.
The replacement regression must keep sequence zero and assure that the
first published bytes already carry SHA-256 of the final snapshot.

### B6 (blocking coverage) — two replay guarantees can regress without an executor test

[snapshot.py:29–35](../../../backend/src/living_island/world/v2/engine/snapshot.py#L29),

Commit both scratch regressions as task-local tests. On the current tip

The reverse input is refused before storage with unchanged state. The valid

fail. These reaching tests protect the new wiring without changing the
freeze or adopting a different addition order.

  provenance in a rule-ID-sorted array. The store writes normalized content
  with provenance. Replay checks canonical content bytes and digest, then
  compares the whole objective event line, catching provenance-only changes.
  Pre-commit I/O may leave immutable bytes for the same pending journal
  batch or rule after an aborted tick. The tests demonstrate retry and
  unchanged world state. A restored segment starts after its snapshot event
  cursor. A last produced packet is still pending until it is ingested.

  `prepare_rules`, as EN-01's review noted. The additions now make both
  paths load-bearing for restore. A small shared rule-layer hash function
  would preserve the frozen algorithm. Journal `ingest` and `verify` also
  project the same batch bytes and acknowledgement IDs independently.
  Share the projection if editing that code for B1 or B6.

  row and envelope), `load_checkpoint` with a mismatched
  `next_journal_tick`, `replay` with the wrong manifest run ID, and the
  no-final-file failure path in `store_once`. Exercise them while touching the relevant boundary
  code or remove redundant checks. The `store_once` fallback can be
  reached when a concurrent publisher has already made the target

  decoded addition and `prepare_rules` provides one callback per accepted

### Remaining B1 — snapshot pending packets bypass boundary identity

[Snapshot restore](../../../backend/src/living_island/world/v2/engine/snapshot.py#L63)
(`restore_snapshot`, lines 63–90) validates shape and re-encodes canonically,
then creates a world without binding its pending packets to that world.
[Checkpoint load](../../../backend/src/living_island/persistence/v2/checkpoint.py#L54)
(`load_checkpoint`, lines 54–75) validates the committed prefix, which
correctly ends before the pending boundary. A valid prefix therefore masks
an inconsistent pending packet in the snapshot. The pending packet is the
one that must be delivered before the next decision under engine §2,
WAP §5.3 and Interface Contract §2.2.

A canonical save can carry a foreign-run delivery ID and still restore.
The scratch reproduction then calls `record_boundary`: the journal ingests
that ID, the world accepts its acknowledgement and advances, and
`PacketJournal.read(0)` rejects the file that this path just wrote.
A different nested actor or tick, an envelope tick from another boundary,
a wrong map key, or a missing living resident's packet is also accepted by
both readers.

Validate as part of `restore_snapshot`, before returning a world. Require
one packet keyed by each living resident, with matching actor, opening tick,
run-derived delivery ID and nested perception identity. Reuse the delivery
identity logic with journal reads where the invariants coincide. Preserve
the original packet value and bytes. The independent
`test_restore_refuses_inconsistent_pending_packet` has six corruptions
through each entry point and genuine snapshot/checkpoint controls.
All 12 refusals fail on the current tip and pass with the scratch check.

### Remaining B2 — a restored active rule can claim approval at or after the saved tick

[Snapshot restore](../../../backend/src/living_island/world/v2/engine/snapshot.py#L77)
(`restore_snapshot`, lines 77–90) passes the saved additions through
`prepare_rules` and reconstructs the active schedule. The opening-tick
approval guard in [`World.step`](../../../backend/src/living_island/world/v2/engine/tick.py#L295)
is never called for those already-active additions. This bypasses rule
