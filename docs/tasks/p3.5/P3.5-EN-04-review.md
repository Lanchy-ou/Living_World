## Findings

### B1 (blocking): physiology coefficients enter untyped, with silent defaults

`apply_physiology` casts the raw pack table every tick
(`cast("Mapping[str, int]", ctx.pack.source.data["physiology"])`) and reads it
with defaults: `rates.get("..._decay_per_tick", 0)`, `rates.get(
"health_recovery_min_...", specs[key].minimum)`. The fatigue coefficients and
`faint_ticks` are read with `rates[...]`. The RR-01 loader only checks that
`physiology` is a table (`loader.py`, `table(pack.setdefault(name, {}))`).

Consequences:

- A pack that enables `stamina` but omits `stamina_awake_decay_per_tick` runs
  with no decay, without any message. The `engine-test` pack does exactly
  this today: it enables `stamina` and has no `physiology` table.
- A pack that enables `mental_fatigue` without `faint_ticks` loads, then
  raises `KeyError` in the middle of a tick.
- A string or negative coefficient is never refused.

This is the fallback pattern the AGENTS.md boundary rule forbids. Engine §9.2
and §9.3 name each value as a pack value; the starter content §4.1 and the
compatibility pack give every one of them.

Requested fix:

- At initialization, build one typed physiology configuration in
  `EnginePack.from_pack` (`validate.py`), as `timing` and `limits` already
  are. For each enabled need, require its values: `satiety` and `hydration`
  their awake and asleep decay and their recovery minimum; `stamina` its
  awake decay and movement cost; `health` its deprivation loss and sleep
  recovery; `mental_fatigue` the four coefficients and `faint_ticks`.
  Integers; decays, costs and coefficients at least 0; `faint_ticks` at
  least 1. A missing or wrong value is refused with the existing
  `lacks engine setting` message or a typed error.
- `physiology.py` reads the typed configuration; remove the cast and every
  default.
- One parametrized test with one row per refusal.
- Give the shared `engine_core` extension in `backend/tests/v2/engine/conftest.py`
  the stamina values, so the shared fixtures state their physiology. Record the
  required-key rule as an open question (the spec names the values but not
  which are required).

This needs an owner-approved scope change: `validate.py` (P3.5-EN-01, merged)
and the shared conftest. No open card edits either file.
