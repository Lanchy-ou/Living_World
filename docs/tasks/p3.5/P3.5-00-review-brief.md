## 1. What P3.5 is for

P3 proves one LLM resident with bounded experience and one goal. P3.5 builds fuller,
extensible versions of the two core systems:

- **World**: a data-driven rule system. Materials have properties, verbs are
  generic, transformations live in content files. Adding content never changes
  the engine.
- **Agent**: memory at the core. Residents are autonomous agents: the model
  chooses every action after seeing the last result, and the world only settles
  what actions do. Each waking period has one growing working context; long-term
  memory is maintained by a model-run consolidation while the resident is
  unconscious.

Acceptance is not a story. It is four preconditions for emergence:

1. Information spreads and is believed or doubted.
2. Rules are discovered, remembered and taught.
3. Artifacts persist and are used by others.
4. Commitments hold across days.

Long term (not P3.5): an LLM proposes new rules that are validated and added to the
rule library. P3.5 only leaves room for this.

Timing: P3 was closed on 2026-11-16 as a delivered foundation; long-duration
proof and the full M10 matrix were deferred, not passed
([P3 closeout](../p3/P3-closeout.md)). P3.5 supersedes parts of the P3 specs
and builds on P3-06 (multi-resident) and P3-07 (inspection artifact), both
merged. Implementation starts after owner acceptance of these ADRs (M11). The
P3.5 milestones M11–M15 and acceptance runs are in the plan, §4; the deferred
P3 items and their dispositions are in §10.

Operating envelope (owner, 2026-11-16), so feasibility can be judged:

- Model: DeepSeek V4.1, context window 1M tokens (to be pinned with provider
  evidence). The P3 per-request limit of 32768 input tokens does not apply.
- No call, token or money cap per resident or per run. Tokens are monitored
  per context section instead (ADR 0012 D4, ADR 0014 D1).
- Measured P3 baseline (offline, default map, one LLM slot, about 27,000
  upper-bound tokens per request): the action schema is 55%, because it is sent
  twice (in the system message and in the structured-output field); tile lists
  are 19%; recalled experience is 20%, half of it metadata. P3.5 sends the
  schema once (ADR 0007 D7).
- Acceptance runs (M15): 5 LLM residents, 7 game days, memory on and off,
  3 seeds per arm, judged by occurrence and traceability rather than rate
  thresholds (plan §4.1). Rough cost estimate: about CNY 900 before cache
  discounts; M14 measures the real figure.

## 2. How the plan was made

1. **Eight systems, one ADR each** (0007–0014), discussed with the owner one group at
   a time. Every owner decision is marked **[Owner]** in the ADRs.
2. **Order follows dependencies**: the world–agent protocol first (everything
   depends on it, and it is a frozen contract), then world (rules, engine, content),
   then agent (memory model, formation, decision loop), then evaluation.
3. **Three layers by change rate**: protocol (rare) / vocabularies (occasional) /
   rule library (frequent). The main design goal: adding rules changes neither the
   protocol, nor the model-facing schema, nor the prompt prefix.
4. **Existing principles kept, not reopened**: the world is the only source of truth;
   perception is not omniscience; deterministic replay with every LLM call recorded;
   no game logic in the frontend.
5. **Reuse P3 where it fits**: experience records, deterministic replay of recorded
   deltas, mandatory/optional context projection, the inspection-artifact pattern.
6. **Unknowns are not invented**: each ADR ends with open questions instead of
   guessed numbers.
7. **Migration without breaking history**: v1 stays frozen; v2 is a new versioned
   lane; old runs are archived by git tag.

## 4. What the reviewer should check

1. **Principle violations**: any path where model output changes world state,
   a resident sees hidden state, the world depends on agent-side data (for example
   token counts), replay needs a new model call, or the world or the harness
   decides what a resident does (for example, stops or replans for it).
2. **Consistency between ADRs**: shared terms (verbs, phenomena, skills, process
   entities, turns, consolidation) mean the same thing everywhere.
3. **Conflicts with frozen specs** that the ADRs do not acknowledge.
4. **Missing decisions**: anything implementation would need that is neither
   decided nor listed as an open question.
5. **Testability**: whether each decision can be checked by a test or a metric.
6. **Scope**: anything that belongs to a later phase (rule discovery, weather and
   seasons, live viewing).

Out of scope for this review: exact numbers, content values and spec-level field
definitions; those come in the per-system specs. A design that cannot work
within the operating envelope (§1) is in scope, even if the cause is a number.

Decisions marked **[Owner]** are not reopened by this review. A finding may
still name one in two cases:

- **Blocking**: it violates a core principle, or conflicts with a frozen spec in
  a way the ADR does not acknowledge.
- **Comment on direction**: a risk or a better alternative the reviewer sees,
  given the P3.5 goals (§1). A comment never blocks acceptance and does not
  affect the verdict; the owner reads it and decides whether to act.

## 5. Known risks the author already sees

- Uncapped model calls (ADR 0012 D4, 0013 D7): cost is monitored, not limited;
  an operator stop is still open (0013 Q3). One call per turn, including turns
  at notifications, means more calls per day than P3 (0013 D2, D3).
- Long-context effects are accepted as limited cognition (0013 D4), but they
  may not appear at the context sizes a day naturally reaches, and they may
  show up first as invalid output, which falls back silently (0013 D7, D8).
- Property-based rule matching can match more items than intended (0008).
- Craftable containers may undercut the P2 water balance (0010 Q3).
- LLM output varies between runs, so metric comparisons need several seeds
  (0014); derived chance rolls (0009 D1) reduce, not remove, this.
- The model's prior knowledge can look like discovery. Only a rule that goes
  against common sense gives clean evidence of learning on the island (0010 D2,
  0014 D2).
- Only agreements with structured terms are checkable; promises made only in
  words are invisible to the commitment metric (0007 D10).
- Fallback actions are kept out of memory and context (0013 D7), so a resident
  may see changes it does not remember causing.
- The v1 equivalence check depends on the rule-based policy reproducing v1
  soft interrupts on its own side (0007 D8).
- The change request for the frozen protocol is not filed yet; it waits for owner
  acceptance of ADR 0007.
