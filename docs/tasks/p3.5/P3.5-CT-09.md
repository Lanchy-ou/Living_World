### Deliverables

- Carry the validator report for every starter rule and its inherited rules, including all admitted branches, with the library and pack hashes. Use a script with typed intents exercising source creation, consumption, transformations and movement over a week. Pin the setup, script and seed. Keep the point-in-time world inventory and ledger calculation independent.
- Start from placed matter, including stores, held items and nested contents. For every declared matter class and each committed boundary count live units by archetype matter × quantity, including stores and container contents exactly once. Reconcile against initial units + admitted source creation − net transformation/sink destruction using RR §§3.4, 8. Convert inputs and outputs per class. A move, transfer, stack split/merge or spill conserves matter. Account for sourced store regrowth and water creation as well as burning, eating, decay and tool breakage. Include the first/last totals, per-source and per-sink subtotals and event IDs for a sample branch.
- Preserve the baseline ledger, cumulative totals, last committed tick and trace prefix on resume. Link the small text summary and a receipt to the full ledger under `runs/m13/`.

### Acceptance (positive, negative, edge, determinism)

- **CT-07.** All starter rules validate. Complete 7 × 144 scripted ticks and reconcile each class at every committed boundary and at tick 1,008. Assert nonzero source and sink flows and include transformed matter. Preserve separate evidence for CT-10's rule-based workload.
- In a small fixture check a source creating into a store, nested/held units, an ordinary transformation, a failed chance that consumes inputs and a transfer/split which changes entity counts but conserves units. Demonstrate a perturbed ledger detects the first incorrect class and tick. A partial week supplies a progress receipt and cannot yield a passing verdict.
- Resume partway through a short fixture and obtain identical per-class totals, ordered ledger and final state without counting an event twice. Include stable links from the summary to the offending rule/branch/event when reconciliation fails.
