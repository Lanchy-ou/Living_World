## Findings

### B1 (blocking, small): events are edited after they are emitted

`emit_speech_event` changes an event after `EventWriter.emit` has appended
it to the log:

- `event.payload[identity_field] = event.event_id` writes the event's own ID
  into its payload (`utterance_id`, `agreement_id`).
- `ctx.writer.events[-1] = event.model_copy(update={"intent_id": ...})`
  swaps the logged event for a copy carrying the companion action's intent
  ID, then appends the ID to that action's `event_ids` by hand.

It works today, but only because nothing reads the event between `emit` and
these edits. If the writer ever hashes, copies or forwards an event at
emission (the persistence and replay card, P3.5-EN-07, is next), these
edits are lost or diverge silently. It is a workaround for not owning
`events.py`, and every later speech event would copy it.

Requested fix (the owner approves this edit to `world/v2/engine/events.py`;
P3.5-EN-03 does not touch that file):

- Give `EventWriter.emit` two optional keyword arguments:
  - `intent_id: str | None`, used when `action` is `None`;
  - `self_id_field: str | None`, which puts the new event's ID into the
    payload under that key before the event is built.
- `emit_speech_event` then calls `emit` once and keeps only the append to the
  started action's `event_ids`.
- Existing callers do not change.
- Add one test: the logged `utterance_spoken` event of an utterance attached
  to an action carries the intent ID and its own ID in the payload, and its
  ID is in the action's `event_ids`.

## Open question for the owner

OQ-P3.5-EN-06 has two parts. The reviewer recommends confirming both as
written.

1. **Deadline.** The start check compares `due_tick` with boundary `t`. The
   emission check compares it with `t+1`, the tick of the utterance event.
   So a proposal due at `t+1` passes at start and is refused at emission.
   This is the stricter reading of "later than the current tick" at each
   check. It also means no one can hear a promise that is already due.
2. **Give by kind.** `{archetype_id, quantity}` terms need only an archetype
   that the pack declares. Exposure applies only to exact IDs and positions,
   which is what §7.2 lists. Possession and feasibility are never checked,
   because the world never judges agreements (§7.2).
