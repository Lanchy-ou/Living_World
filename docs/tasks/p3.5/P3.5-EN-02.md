## Handoff

### What changed

Implemented the v2 act lifecycle using the existing engine tick hooks. It
matches exact target and item slots, selects by specificity and rule ID,
captures a replayable attempt descriptor, and reserves physical portions
with the original IDs retained in feedback. Completion rechecks the chosen
rule and uses an identity-keyed chance roll.

The branch ledger captures operands before effects and publishes quantities,
placements, allocation IDs, needs and event records together on admission.
It handles lose and partial interruptions, resource contention, spills and
merges, and records the consumed and returned physical portions. Added 79
settlement tests using the shared `pack`, `setup`, and `world` fixtures.
The tests include the three Round 3 cases and the pack extension with its
conservation refusal.

### Deviations

The shared engine fixtures were reused directly. The code splits resolved
oversized stacks after the start match and conditions capture, including
fixed outcomes that passed the generic checks. The original views remain
available after release or consumption.

When rule work changes needs, `progress_act` applies the gains and returns
the pre-progress values for the phase 5 journal and crossing calculations.
The pinned tick caller discards that return. The shared tick integration
must feed those values to P3.5-EN-04's physiology hook. This card verifies
the returned values and the settlement-owned state effects.
