## Blocking

### R5-B01 — Adding a source to I can still require the forgotten T

**Location.** MM §§2 and 4.2, MF §3.5, and the existing forgetting
and checkpoint rules referenced by R25.

**Conflict.** Rework 5 preserves the ancestry bit on I and uses it when
another record cites I. It also requires that an update adding a source
recompute the candidate's bit from its sources and the bits of each cited
revision, using the sent input or staged store. For an update to I itself,
the pre-existing direct citation is to T. Neither input contains T after
forgetting and restore. The new requirement to recompute on source changes
does not say to carry forward I's stored summary of unchanged sources.

**Counterexample.** Use the original T→I case, with I at confidence 3.
Forget T and restore. Have the next consolidation read I in full and
submit a valid `update.add_sources` adding one delivered observation about
I's subject. The source is authorized and the record stays within the
confidence cap. The existing inferred source still points to T. The
literal recomputation cannot finish from the permitted inputs, although
I already holds the correct answer. The observed-only T control has the
same missing lookup and must preserve a false summary when the new source
is observed.

**Minimum correction.** For append-only source changes, combine the
current staged revision's bit with speech ancestry of newly added
sources. A merge can likewise combine the input revisions' bits with
new sources. Existing immutable source bindings stay in place and need
no lookup. Continue testing the final confidence on the candidate and
keep the audit outside validation. Add a restore case that updates I
itself with a valid observation at confidence 3, then cites the updated
I from a fresh candidate at 4. Exercise both the told and independent
ancestor cases.

counterexample also gave the candidate a valid observed source. Carry
that source into both arms of MM-25 so that the comparison isolates
speech ancestry. The confidence rule itself is explicit.
