## Regenerate the ledger offline

```sh
uv run --offline --no-env-file --directory backend python -m living_island.analysis.v2_spend sanitized-evidence.json
```

Substitute an absolute path to a local JSON file for `sanitized-evidence.json`, or give a path relative to `backend`. The command writes a Markdown report to stdout. Archive the sanitized bundle with the run receipts and copy the generated rows into this ledger. DL-06 owns the provider-check update, followed by EV-06 for the resident-run update. Use one writer at a time. Regenerate the phase totals from the accumulated evidence for both stages on each update.

An empty snapshot with an unresolved opening can be reproduced with the following input.

```json
{
  "opening": {"settled_cny": null, "source": null},
  "tariffs": [],
  "runs": {}
}
```

### Assemble the evidence bundle

| Field | Evidence to include |
| --- | --- |
| `opening` | `settled_cny` is a decimal CNY string or `null`. `source` points to the dated reconciliation for the period before the first included dispatch. Record a zero opening only when supported by evidence. Keep the opening amount disjoint from the individual attempt rows. |
| `tariffs` | Each row has `provider`, `model` (alias), `model_version`, `effective_on`, `through`, `source` and `model_evidence`. Use nonoverlapping, inclusive ISO dates (`YYYY-MM-DD`) for each model. Pin the resolved model and a dated source for `cache_hit_per_million`, `cache_miss_per_million`, `output_per_million`, `peak_cache_miss_per_million` and `peak_output_per_million`. Each rate is a decimal CNY string with up to six decimal places per million tokens. Collect coverage for every UTC dispatch date, including retries. |
| `runs` | Key this object by the immutable run ID. Each value has `stage` (`provider_check` or `resident_run`), `mode` (`paid` or `fake`) and `date` (`YYYY-MM-DD`). Use the same run ID after restore. Label rehearsals and fixtures `fake`. |
| `prepared`, `dispatches`, `terminals` | For each run, include arrays of the inline JSON facts from the journal. Keep the dispatch even if its terminal fact is missing. |
| `abandoned`, `undispatched` | Include abandoned call IDs from recorded host dispositions. Add pre-prepare calls in `undispatched` from the host record with `call_id`, `kind`, `provider`, `model` and `model_version`. A prepared floor with no dispatch is already represented by its prepared fact. |
| `charges` | Match provider or invoice evidence to a run and its `call_id` and zero-based attempt `n`. Include `source` and any available `provider_cny` and `invoice_cny`, as decimal CNY strings with up to twelve decimal places. Tie a zero charge to a verified settlement record. |

The DL-01 journal stores `<call-hash>.prepared.json`, `<call-hash>.<n>.dispatch.json` and `<call-hash>.<n>.terminal.json` as flat cursor files inside each run. The call hash is the SHA-256 of the UTF-8 call ID. Parse each selected cursor as JSON and put its object in the corresponding array. Preserve the prepared and dispatch cursor references inside the facts. Check the archived source run and its recorded pins before assembling the bundle. Keep content-addressed request and response bodies, prompts, reasoning blobs, authorization headers and credentials out of the bundle and ledger. [DL-01 journal handoff](P3.5-DL-01.md#handoff)

The operator supplies the evidence sources, opening scope, run provenance and tariff coverage. Verify those declarations against the retained receipts before using the report. An omitted dispatch or an opening reconciliation that covers the same attempts as the bundle would change the reported balance.

### Reconcile actual and partial records

1. Join dispatches and terminal or billing evidence by run ID, call ID and attempt number. Retries and different attempts with identical wire bytes have separate charges. Use the existing identities after interruption or restore. Preserve late usage on the same attempt and project the updated bundle once it is recorded.
2. Read the cache hit, cache miss and output token columns as actual measured usage. Keep unknown categories visible. Hold the pinned worst-case reserve for a possible charge with missing usage or cache split, inclusive of peak uncached input and allowed output. An error, interrupted request or abandoned workflow can still have provider charges. A `stopped_unfit` floor without a dispatch has zero charge and zero reserve.
3. Check calculated usage charges against any provider or invoice evidence. The attributable invoice amount takes precedence, followed by the attributable provider-reported charge and then the calculated usage charge. When both reported amounts exist, retain them in the same charge row for that attempt. The invoice delta uses the provider amount when available and otherwise the calculated charge. Release the corresponding reserve once settlement is recorded. An unbounded liability or an invalid bundle blocks further dispatch. Review errors and balance differences before relying on the result.

## Cost sizing sheet

Include an optional top-level `plan` with `stage`, `date`, `provider`, `model`, `model_version` and `rows`. Each row has `day`, `kind`, `n`, `count`, `input_bound`, `output_bound` and `central_cny`. `day` is `null` for the provider check and a positive game-day number for the resident run. `n` is the zero-based attempt ordinal and `count` is the positive number of occurrences with those bounds. The bounds are token counts, or `null` when unestablished. `central_cny` is an optional decimal CNY estimate per attempt, or `null` when unavailable. Split rows when bounds or central estimates differ. Keep fixed, measured and unknown values traceable to each row's source receipt.

| Call kind | Provider check logical calls | Resident run input for each candidate day |
| --- | ---: | --- |
| `decision` | 1 | EV-05 logical calls and attempt counts, sent sizes and growth |
| `decision_after_recall` | 1 | EV-05 logical calls and attempt counts, sent sizes and growth |
| `recall` | 1 | EV-05 logical calls and attempt counts, counted query and index |
| `morning` | 1 | EV-05 logical calls and attempt counts, counted state and index |
| `consolidation_selection` | 1 | EV-05 logical calls and attempt counts, counted period context and overlapping work |
| `consolidation_change_set` | 1 | EV-05 logical calls and attempt counts, counted selected and changed records and overlapping work |

For each kind and attempt ordinal, use the evidence-backed maximum input for the actual provider-framed request and its allowed output. Multiply those tokens by the dated peak uncached input and output rates and divide by one million. Multiply by the row's `count` to get its reserve. Include the permitted retry exposure through the next safe stop, including overlapping consolidation. Use the worst-case supported bound for any planned dispatch whose input can still grow. The central estimate uses comparable DL-06 measured costs and EV-05's attempt counts, adjusted for later-day request growth. Keep it separate from the conservative sizing result. ## Operator admission

Recompute headroom before each paid unit of work as CNY 20 less evidence-backed opening spend, settled P3.5 attempts and outstanding reserves. Compare the full planned exposure through the next safe stop to that headroom, counting already-dispatched attempts in outstanding liabilities and future attempts in the plan. A successful report can say `WITHHOLD` when exposure exceeds headroom or cannot be bounded, or the opening spend is unresolved. The operator enforces that result at the dispatch boundary.

For the resident run, use the largest consecutive prefix of whole game days whose cumulative conservative cost fits. A day is 144 ticks. If fewer than three complete days fit, hold EV-06 and take the measured shortfall to the owner. Both paid steps also require the signed M12 Gate 3 and the owner's release for the particular run. No dispatch authority follows from an affordable projection alone. [M14 plan §§1 and 5](M14-plan.md)
