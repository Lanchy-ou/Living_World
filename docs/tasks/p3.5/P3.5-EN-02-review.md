## Findings

### B1 (blocking): sleep start and phase 5 are not wired to physiology

Two lifecycle points meet P3.5-EN-04's code, and both are left open:

- `record_act_started` sets `awareness` to `asleep` and emits
  `resident_fell_asleep` itself. P3.5-EN-04 adds `physiology.start_sleep` for
  the same transition. After both merge, two functions own one transition.
- `progress_act` returns the pre-progress need values, but the tick drops
  them, and calls `apply_physiology(ctx)` and `hard_stops_and_waking(ctx)`
  without `ProgressNeeds`. So the phase 2 rule effects never reach the one
  `needs_changed` event of engine §9.2 step 6, and a waking crossing caused
  in phase 2 is judged without its opening value (protocol §6.3, WAP-24).

Both handoffs flag this as a shared follow-up, with no card owning it. The
combined run shows it: the 10 sleep tests of P3.5-EN-04 fake `start_act`
without a `rule_id`, and this branch's `progress_act` then fails with
`KeyError: None` (`settle.py`, `ctx.pack.source.rules[cast(str,
action.rule_id)]`). Each card passes alone.

Requested fix, after P3.5-EN-04 merges and this branch rebases on it:

- `record_act_started` calls `physiology.start_sleep`; remove the duplicate.
- The tick collects each actor's `progress_act` opening values and the rule
  IDs into `ProgressNeeds` and passes the same mapping to
  `apply_physiology` and `hard_stops_and_waking`.
- Replace the `sleep_settlement` seam in P3.5-EN-04's
  `tests/v2/engine/physiology/` with a real sleep rule in that test's pack
  extension, so those tests run the real start, progress and completion and
  pass again.
- Tests through the real tick, without monkeypatched settlement: a per-tick
  need rule plus physiology in one tick gives one `needs_changed` whose
  `causes` hold `physiology` and the rule ID and whose `before` is the
  pre-progress value; a crossing caused by a per-tick effect wakes a
  sleeper with `WOKEN`; a sleep chosen at boundary `t` first shows `asleep`
  at `t + 1` (EN-24) through the real `start_act`.

This needs an owner-approved scope change: `tick.py` (P3.5-EN-01; one branch
at a time, M12 plan §3), a call into `physiology.py`, and the P3.5-EN-04
physiology tests. All belong to merged cards by then, so no open card edits
them.

### B2 (blocking): specificity is computed twice

`match.specificity` recomputes rule specificity (target predicates, slot
predicates, conditions). The RR-01 loader already computes it once
(`rules/rule.py` `specificity`) and stores it as `Rule.specificity`, which
RR-11 tests. Two formulas for one ranking will drift: the loader's counts the
`subject` keys, this one does not. Today no verb rule has a subject, so they
agree.

Requested fix: sort by `rule.specificity` and delete `match.specificity`.
