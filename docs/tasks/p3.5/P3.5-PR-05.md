## Handoff

### Phase A

Added the v2 packet-to-submission agent port and per-actor scripted agent.
The coordinator delivers packets, schedules turns, attaches harness-owned
identities to model choices, and passes ordered submissions and
acknowledgements to the world. The in-memory manifest records committed
fallbacks and a terminal stop witness at the frozen boundary. The packet
tests cover eligibility, notification, continue, ordering, fallback
ordinals, rejected submissions, and terminal stops.

Implementation commit `2a7a4bfc77480951df80672028a7a5a244e00493` is based on `bb21352`.
Locked backend sync, `ruff check .`, `ruff format --check .`, `mypy src`,
and `lint-imports --no-cache` passed (13 contracts).
`pytest tests/v2/sim tests/p3/test_trial_registration.py` passed all 42 tests
in one session with command-scope Git long paths and a fresh Windows base directory.

Phase B waits for EN-05 and EN-07 before testing WAP-02, WAP-12, and WAP-16
on the real `World` and running full Gate 1. The recall call manifest
(DL-20/DL-27) belongs to M14.

See [OQ-P3.5-PR-05](../../spec/open-questions.md#oq-p35-pr-05-read-access-to-the-frozen-boundary)
for the Phase A read-only use of `World.state` and the pending-packet
binding check to confirm in Phase B.

### Phase B

The coordinator journals the exact EN-05 packet batch before delivering it.
A refused submission leaves the world frozen and records the refused batch.
A retry uses the already delivered packets. Committed boundaries retain
submissions, canonical event bytes and fallback facts for EN-07 replay.
The harness supplies a terminal witness. That path preserves the frozen
world and commits neither a submission nor a fallback.

| Acceptance | Evidence |
| --- | --- |
| WAP-02 and protocol §1 | Real runner submissions bind with zero-padded turn IDs at ordinals zero and one. The negative vectors and committed-turn resubmission are refused atomically. The retry commits a fallback and advances each ordinal once. |
| Protocol §2 and decision loop §2.1 | The Phase A scheduling vectors cover start, wake, action end and unconscious residents. In the real run, addressed speech triggers a notification while movement runs. `continue` keeps the original intent through completion. |
| WAP-12 | Different policy paths produce the same submissions, actions, non-fallback events and packets. The submission shape excludes agent-private fields. |
| WAP-16 | Three recorded boundaries replay with two fallback facts, identical packet and report bytes, objective event bytes and snapshots. Replay invokes no decision or packet delivery callback. |
| Round 3 unfit recall | A real terminal stop keeps the same snapshot and pending packets, journals the frozen batch, records the witness and commits no submission or fallback. DL-20 and DL-27 remain M14 work. |

### Deviations

Under M12 runbook §§5 and 6.1 the serial card used these two merged paths
for WAP-16:

- `backend/src/living_island/world/v2/engine/tick.py` accepts typed
  fallback facts as a separate boundary input and appends them through the
  canonical event writer after the engine phases. This keeps settlement,
  resident packets and intra-tick settlement event IDs policy-neutral.
- `backend/src/living_island/persistence/v2/replay.py` keeps the separate
  facts with the recorded boundary and supplies them to the same writer on
  replay so the objective log can be compared byte for byte.
