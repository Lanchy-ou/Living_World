### B1 (blocking) — a callback can answer a different resident's turn

`backend/src/living_island/sim/v2/runner.py:71–94`, `Runner.advance`, collects
answers and sorts them by returned actor. The engine's `bind_turns`
in `backend/src/living_island/world/v2/engine/validate.py:495–531` looks up
each returned actor's current identity. It has no association between an
answer and its outstanding `TurnRequest`. WAP §3.1 assigns that check to
`sim` before the world port.

`test_runner_rejects_swapped_callback_answers_before_world_step` returns
`res_b`'s valid fallback answer from `res_a`'s callback and `res_a`'s valid
answer from `res_b`'s. Both commit today. Bind each typed callback answer,
including the fallback wrapper, to the originating request's actor, tick and
turn ID before batch submission. Keep the nested identity contract on that
binding path and retain world ingress checks for direct and replay callers.
The probe must pass with `INVALID_TURN`, a refusal record, zero world-port
calls and the original snapshot and ordinals. Keep the same-boundary retry
test passing. Adjust the runner seam test
`test_invalid_submission_is_left_to_the_world` to assert the pre-port
refusal while retaining its no-commit and ordinal checks.

### B2 (blocking) — fallback metadata can claim a turn that did not commit

`backend/src/living_island/world/v2/engine/tick.py:295–307,325–337`,
`World.step`, emits every supplied `FallbackFact` after settlement. The typed
input is independent of the already bound turns. In
`backend/src/living_island/persistence/v2/replay.py:104–113`, `replay` supplies
the same input and compares against the recorded bytes. A self-consistent
record can reproduce a false fact. WAP §9 and decision loop §8.3 put the
objective tag on the substituted turn.

`test_world_refuses_fallback_metadata_without_one_matching_committed_turn`
submits `res_a`'s valid turn. A tag for unmatched `res_b`, a tag for `res_a`'s
next ordinal and a duplicate tag all commit today.
`test_replay_rejects_self_consistent_fallback_tag_for_an_unsubmitted_actor`
first replays a valid tag, then shows replay accepts an orphan when the
recorded metadata and event bytes agree. Check this metadata once against
the bound actors and turn IDs before rule storage or advancement. The
probes must pass with atomic refusal in all direct rows, and replay must
refuse the orphan while still replaying the valid control byte for byte.
Preserve late emission to keep events and packets policy-neutral. Extend
the real WAP-16 test to assert the full objective payload, including distinct
fixture values for `reason` and `fallback_policy_id`. The assertion must fail
under the payload swap and pass on the corrected wiring.

### B3 (blocking) — the packet cache loses scheduling facts and partial delivery progress

`backend/src/living_island/sim/v2/runner.py:59–75`, `Runner.advance`, gives
`deliver` the same detached packet that it caches and later uses to schedule
turns. `BoundaryDelivery.reports` is a mutable list inside the frozen model.
EN-07's accessor protects `World.state`. The runner still shares its
scheduling input with callbacks, contrary to the immutable delivery contract
in WAP §5.3 and the unconditional action-ended turn in §2.

`test_receiver_cannot_remove_action_ended_from_coordinator` checks that the
real journal is already readable in the receiver, then clears the received
reports. Both real wait actions end and both tick-one turns disappear. Keep
a pristine runner-owned packet for scheduling and retries. Give both callbacks
detached values. The probe must pass with both tick-one turns, matching frozen
journal bytes and the existing receiver contract for notification promotion.

`test_delivery_retry_preserves_an_earlier_successful_callback` lets `res_a`'s
receiver return normally and makes `res_b`'s receiver fail before ingestion.
The snapshot and journal remain frozen but retry delivers `res_a` again
because the tuple assignment happens only after all receivers return.
Retain delivery progress per successful callback. The test must pass with
receiver calls for `res_a`, `res_b` (failure), then `res_b` (retry), and one
decision per resident after both successful deliveries.

### B4 (blocking) — callbacks can rewrite recorded submissions and the stop witness

`backend/src/living_island/sim/v2/runner.py:75–104`, `Runner.advance`, publishes
callback objects inside `BoundaryRecord`, `FallbackTurn` and `StopRecord`. In
`backend/src/living_island/sim/v2/manifest.py:12–51`, the wrappers freeze
assignments to fields while nested `params`, lists and the JSON witness remain
mutable. The event bytes have already been captured when those aliases change.
This undermines WAP §12 and the card's terminal witness requirement.

`test_committed_submission_does_not_alias_callback_output` edits a retained
answer after commit and sees the change in both the recorded submission and
its fallback wrapper. `test_terminal_witness_does_not_alias_callback_output`
changes the measured floor after stopping and observes the logged value change
from 90 to 1. Take ownership of each received submission and terminal witness.
Use the owned values for settlement, the manifest and replay.
`test_mutating_old_fallback_answer_cannot_break_replay` confirms valid replay
first, then replay fails shape validation after editing the old object.
All three probes must pass, including replay of the original event and
snapshot bytes after the caller changes its old object. Apply the same
ownership to refused batches.
