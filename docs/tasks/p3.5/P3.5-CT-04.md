### What changed

`runtime.run_or_resume(directory, plan, setup)` runs one case in a stable directory. The setup factory returns an initialized world, source blob digests, a packet script or stand-alone policy session factory, and a boundary observer. The observer can read the opening packets, committed turns, objective results and closing snapshot. Its accumulated measurements live in the sim checkpoint alongside the script cursor or per-resident policy state. `runtime.replay_case(directory, pack)` replays a verified checkpoint prefix from recorded turns.

`inputs.json` pins the opening snapshot, content ancestry, vocabulary, library, source and effective config/map hashes, seed, controller, observer, setup, revision, runner, index, arm, horizon and timing settings. The EN-07 journal stores one batch per observed tick. Each checkpoint binds the complete prefix of packet and turn/event bytes by SHA-256. Checkpoint publication validates the newly covered journal segment. Resume verifies the entire committed prefix before advancing. The case-local SQLite file records checkpoint locations and attempt history and serializes writers.

`Progress` returns the last recoverable tick and checkpoint, timing, and an optional verified `Evidence` record. At the full horizon, `evidence.json` contains the run ID, case index, tick range, input/checkpoint/final-snapshot/prefix digests, checkpoint locator, reporter totals and provider-call count. This is the artifact for PR-07's completion receipt. Timing covers setup, recovery, attempted work, journaling, checkpoint writes and verification through the first durable evidence handoff. Each tick updates the monotonic elapsed sample. Clean inter-attempt gaps count as downtime. The unmeasured tail of a killed process remains a separate gap and leaves a budgeted verdict indeterminate.
