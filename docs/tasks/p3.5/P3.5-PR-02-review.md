## 2. Blocking findings

### B-01 — Watching exposes an unobserved action target

**Location:** Protocol §§3.2, 5.4, 13/WAP-08; specifically the
`ObservedAction.target` field and the actor-visibility delivery condition.
Basis: ADR 0007 D10; World Rules §4.2.

**Problem.** Section 5.4 delivers an observation when the actor is visible
at an action's start, stop, or settlement. It expressly includes the target,
but supplies no watcher-specific target filter. Filtering `visible_items`
and watcher-visible phenomena does not filter the separate `target` field.
ADR 0007 D10 permits physically visible attempts, items, and phenomena; it
does not make another resident's remote navigation choice observable.

**Concrete counterexample.** A and B can see each other. A starts
`move_to` toward a distant tile in A's explored footprint, outside B's
sight and explored footprint. Such a move is legal under the inherited v1
movement semantics. Copying A's target into B's `ObservedAction` tells B
the exact destination before A has travelled there or said where it is going.
A visible actor manipulating an entity obscured from the watcher produces
the analogous entity-reference leak.

**Recommended fix.** Define `ObservedAction.target` as a projection for
that watcher, not a copy of the submitted intent. Include a reference only
when the target is physically observable in the action observation; otherwise
redact it, for example with the already permitted `null`. Specify how this
projection updates exposure receipts. An unobservable destination or target
must not become an authorized reference merely because another resident
selected it.

**Missing test.** Extend WAP-08 with a visible actor and an unseen destination,
and with an occluded entity target. Assert both redaction and absence of a
new receipt for the hidden reference. A paired visible-target case must still
deliver the observable reference.

### B-02 — The world-side precondition contract is incomplete

**Location:** Protocol §§3.2–3.4, 4.2–4.3, 6.2.

**Problem.** Section 3.4 sends implementers to “Kernel preconditions (§4.2),”
but §4.2 is a failure-code catalog. The inherited v1 table supplies useful
semantics for existing actions; it supplies none for the new `inspect`,
`contribute`, and entity-target `drop` operations. The expanded
container/process pickup cases also need explicit applicability of reach,
capacity, and existence checks.

For generic `act`, §3.3 already requires existence checks, but the ordered
list in §4.3 names only life, receipts, held inputs/instruments, and reach.
It does not place target existence in that order or prescribe its start
failure. This is an incomplete ordered list, **not** an absence of any
existence requirement.

**Concrete counterexamples.**

- A resident has a valid old receipt for a distant open process and submits
  `contribute`. The text does not select a same-tile, adjacent, or other
  content-declared physical reach rule for that kernel action. Implementers
  must invent the condition that separates a legal contribution from
  `OUT_OF_REACH`. A remote `inspect` raises the same problem for access to
  `on_inspect` properties.
- An `act` references an exposed entity that has since disappeared, while
  an input is also no longer held. Section 3.3 requires checking existence,
  but §4.3 does not say where it sits relative to `NO_ITEM` and reach.
  The selected failure code and the distinction from a target disappearing
  during an already running action are therefore not pinned.

**Recommended fix.** Add a kernel precondition table covering the new and
expanded actions. State or explicitly inherit reference authorization,
target existence/type/liveness, holding, physical reach, capacity, transfer
atomicity, and mutable completion revalidation. Map each check to its
failure code. Refer to named content parameters where values belong to
starter content; this review does not choose those values.

Complete the ordered generic checks, preserving receipt authorization
**before** live lookup. Specify the outcome for a target missing at submission
and distinguish it from the running-action `TARGET_GONE` hard stop. State
which failed check wins when several apply.

**Missing test.** For each new kernel operation, cover in-reach, out-of-reach,
wrong-kind, and missing targets. For generic `act`, combine a stale
authorized target with a missing input to assert failure precedence. Compare
a missing-at-start target with disappearance during execution, including
elapsed time and whether `on_interrupt` runs.

### B-03 — Turn identity and observed boundary need explicit validation

**Location:** Protocol §§1, 2, 3.1–3.4; replacement of Agent Interface §3.1.

**Problem.** The new DTO repeats `actor_id` and `turn_id` inside the
nested intent and adds `observed_tick` to the submission. Section 1 defines
ID formatting, and §2 clearly describes resident-local turns. However, §3.4
does not carry forward the predecessor's explicit checks that the actor,
request tick, and generated IDs match the authorized decision.

The intended architecture is actor-local; this finding does **not** claim
that the design authorizes cross-actor execution. The missing part is the
validation invariant and rejection behavior at the new port.

**Concrete counterexample.** The delivered turn belongs to A at boundary t.
The outer submission names A and A's current turn, but its nested, otherwise
well-shaped `wait` intent names B and a correctly formatted B turn ID.
Both ID strings individually satisfy the format. None of the enumerated
§3.4 checks expressly binds the nested intent back to the delivered turn.
Rejecting the object, overwriting its fields, and trusting one of its actor
fields are different implementations of an unstated binding rule.

A submission with a stale `observed_tick` has the same omission even
when every ID agrees.

**Recommended fix.** State which identity fields the host assigns and which
it validates. Before the world port receives the submission, require the
outer actor, nested actor, outer/nested turn IDs, intent ID, current ordinal,
and delivered boundary to agree. Define stale/duplicate submission handling
and ensure rejection does not commit the ordinal twice or partially apply
an action. Use the existing agent-side `INVALID_TURN` classification for
a malformed binding, or name another explicit pre-world contract if intended.

**Missing test.** Foreign nested actor/turn, stale boundary, malformed intent
ID, and duplicate/current-ordinal mismatch must have prescribed outcomes.
Assert no world effect and exactly-once ordinal advancement for the accepted
or fallback turn.

### B-04 — v1 urgent crossings cannot be recovered from need bands

**Location:** Protocol §§5.3, 6.3, 11.2; Interface Contract §2.5;
World Rules §§4.3–4.4.

**Problem.** The compatibility adapter must reproduce the v1 interruption
table, but the world reports only `need_band_changed`. The frozen contract
explicitly defines urgent crossings by exact authoritative thresholds,
**not** NeedBand changes. The information needed to reproduce those
crossings is absent from the new reports.

This also affects sleep: §6.3 gives sleepers no turn and allows early waking
only at critical hunger/thirst. Keeping v1 sleep decay rates does not
preserve v1 wake timing.

**Concrete counterexample using the pinned default rules.** The
[configuration][C] has band cutoffs `[2000,4000,6000,8000]`, urgent
satiety/hydration thresholds of `3000`, and an urgent stamina threshold of
`2500`. Hydration decays by `100` per tick; sleep lasts `48` ticks.
These are existing v1 values used to test migration, not proposed v2 values.

Take a synthetic checkpoint with hydration 7000, stamina 1000, adequate
satiety/health, and no higher-priority policy action. The frozen policy's R7
can choose sleep in this state.

| Boundary | v1 | New compatibility behavior as written |
|---|---|---|
| 40 | Hydration crosses 3100 → 3000; unfinished sleep is interrupted by `URGENT_NEED` | Both values are still `low`; no hydration-band report and no critical-band wake |
| 48 | The v1 actor has already had an opportunity to act for eight ticks | Sleep naturally completes at hydration 2200, without ever reaching `critical` |

The action-outcome timing differs before any model behavior is considered.
If the awakened v1 actor waits, its awake stamina decay also differs from
continued v2 sleep recovery. The same information loss occurs during awake
rest or movement: identical bands and band-change reports cannot identify
which state crossed 3000.

The v1 implementation corroborates the specification in
[interrupts.py][INT], `observations` and `soft_interrupt`.

**Recommended fix.** Specify the compatibility mechanism that preserves the
frozen crossing facts and sleep wake rule, while preserving PR-D6's accepted
new-world behavior. A neutral, pack-defined threshold-crossing fact can
supply the compatibility harness with the old crossing without exposing
exact need values or asking the world to decide an awake resident's next
action. The compatibility sleep exception must also be explicit: a report
alone cannot offer a turn to a resident who remains asleep.

Do not silently change the old band cutoffs to encode urgent thresholds:
that changes the frozen policy's inputs.

**Missing test.** Script all three v1 urgent crossings inside a band,
including an unfinished sleeper. Test already-below-threshold non-retriggering,
completion on the crossing tick, and co-occurring urgent/direct-speech/new-sight
facts with the old priority and trigger retention.

### B-05 — Failed speech is not reconstructed as a failed v1 talk action

**Location:** Protocol §§7.1, 11.2–11.3; Agent Interface §3.2;
rule-policy §§5–6.

**Problem.** A v2 utterance can fail while its accompanying action succeeds.
That is the accepted v2 speech design. But the compatibility translation
`talk → utterance + wait` does not define the composite logical result
the frozen policy must receive. The ordinary action-result projection cannot
turn a successful wait into the failed v1 talk result without an additional
adapter rule.

**Concrete counterexample.** Use the actual default durations:
`talk_ticks = wait_ticks = invalid_attempt_ticks = 1`. Let an adjacent
pair's last allowed dialogue utterance be a request. The addressee then
has the validly shaped v1 plan:

`[talk accept(in_reply_to=request), give fruit × 1]`

The accept exceeds the pair's dialogue cap.

- In v1, talk fails with `DIALOGUE_LIMIT` at the next tick. The runtime
  discards the queued gift, and the policy can apply its failed-talk back-off.
- In v2, the utterance fails with `DIALOGUE_LIMIT`, but the surrogate wait
  succeeds, as §7.1 requires. Sections 11.2–11.3 do not reconstruct the one
  failed logical talk result and trigger needed to discard that same queue.

The [rule-policy specification][RP] explicitly relies on failed talk
discarding the queued give. Fixing only the comparison output would not fix
the policy's next decision.

**Recommended fix.** Define a logical v1 talk result joining the corresponding
utterance feedback and surrogate wait. Specify their identity linkage,
exactly one reconstructed result, failure code, trigger, queue disposal,
and back-off behavior. Preserve the v2 rule that speech failure does not
cancel an ordinary physical action.

Complete the accompanying speech conversion contract: reconstruct
`request` and its item type/quantity from compatible `propose` terms,
map reply identities, and specify how the compatibility utterance order
relates to v1 completion order. The inverse conversion is intended by the
adapter description, but an explicit testable mapping is still needed.

**Timing qualification.** The pinned default's equal one-tick durations
avoid a separate duration mismatch. For a legal v1 profile with
`talk_ticks > 1`, v1 emits at completion, whereas §7.1 emits at t+1.
Making the sole `wait_ticks` equal `talk_ticks` also changes ordinary
waits if those old durations differ. Either support these profiles through
an explicit compatibility mechanism or state the supported profile and
load-time restrictions. This is not a claim that the pinned default has
unequal durations.

**Missing test.** Compare the failed accept-plus-give sequence, projected
feedback, and next policy behavior for `DIALOGUE_LIMIT`,
`OUT_OF_HEARING`, and `INVALID_REPLY`. Add a request/proposal round trip
and simultaneous-utterance order fixture.

### B-06 — Terminal-result and timing projections are not complete

**Location:** Protocol §§4.2–4.4, 11.2–11.3.

**Problem.** Section 11.3 maps every v1 `interrupted` result to
`stopped` by the actor. That is wrong for death and does not describe
early world waking. It also lacks an explicit time-preserving distinction
between a rule attempt already unmet at start and a previously admitted
action becoming unmet at completion.

**Decisive counterexample: death.** An unfinished six-tick rest ends in
deprivation death after its first tick. Frozen World Rules §4.3 requires
`interrupted/DEATH`; the [v1 engine][ENG] implements that transition.
Protocol §4.4 requires `stopped/{by:"world",reason:"DEATH"}`.
The projection instead requests an actor stop. A dead actor cannot make that
choice. This is an explicit mapping contradiction, independent of whether
a particular acceptance seed happens to encounter it.

**Additional projection cases requiring a pinned oracle:**

| v1 case | Required compatibility distinction |
|---|---|
| Urgent interruption of awake work | Reconstructed policy choice to stop, preserving the old reason/priority in the v1 projection |
| Urgent early wake from sleep | World `WOKEN`, once B-04's timing is fixed; not an actor decision while asleep |
| Start failure at an empty tree | Bounded invalid-start duration |
| Last-fruit contention between two valid gathers | The loser retains the work time already elapsed before its completion failure |
| Gather with no stamina or capacity | Old `EXHAUSTED`/`INVENTORY_FULL` must be accounted for if represented by unmet rule conditions; §11.3 currently maps only dropped codes to `unmet` |
| Successful or failed item transfers | Resolve old item-type/tile inputs to the new instance references deterministically, including stale references |

For the timing example, the pinned v1 values are
`invalid_attempt_ticks = 1` and `gather_ticks = 2`. An empty-at-start
tree fails at t+1. Two valid gathers competing for the last fruit settle at
t+2, including the loser. Sections 4.3 and 11.2 cannot be interpreted as
assigning one tick to every final `unmet` result. The world-engine spec
owns the phase algorithm, but the compatibility projection needs a clear
elapsed-time invariant that it must satisfy.

The “same name” row for `give`/`pick_up` also omits real shape conversion:
v1 pickup names a tile and item type; v2 names an item entity. This is not
identity conversion merely because the action name is unchanged.

**Domain qualification.** A structurally valid v1 `eat` with no fruit has
no held fruit instance for the §11.2 translation, although v1 returns
`NO_ITEM`. This is useful negative-case coverage, but the frozen rule
policy does not choose eat with an empty inventory. It is therefore not
presented as an observed or inevitable P2-policy failure. The compatibility
contract should say whether such scripted v1 intents are in its supported
domain and, if so, how they map without inventing an authorized item ID.
The same care applies to other negative attempts that the baseline policy
normally avoids.

**Recommended fix.** Provide a terminal mapping table that distinguishes
world death, world waking, actor choices, start failures, and completion
failures, with the original failure/reason and elapsed-time projection.
State deterministic reference conversion and the supported adapter domain.
Where the runtime policy consumes projected feedback, define that projection
as well as the evaluator's projection. Keep private rule IDs and settlement
types out of model-facing feedback.

**Missing test.** Add unfinished death, completion followed by death in the
same tick, natural and early waking, empty-at-start versus contested-at-completion
gathering, and retained-code failure mappings. Add deterministic transfer
reference cases and explicit supported-domain tests. These fixtures must
assert ticks and the next policy decision, not just the final inventory.

## 3. Non-blocking findings

### N-01 — Accepting speech has two “right after” event instructions

**Location:** Protocol §9, rows `utterance_heard` and
`agreement_accepted`; §12; WAP-09.

**Problem and concrete counterexample.** Section 9 retains v1 ordering and
says the sorted listener events occur right after `utterance_spoken`.
It also puts `agreement_accepted` right after that same accepting
utterance. If A and C hear B accept, the text does not clearly select between
the listener block followed by agreement acceptance and agreement acceptance
followed by the listener block. Event sequence numbers and IDs differ.

**Recommended fix.** State one complete local sequence. Preserving the
inherited v1 listener-block rule would put `agreement_accepted` after
that block. Preserve backward-only causal references. This is a narrow
wording correction, not a new speech design.

**Missing test.** WAP-09 should assert the entire accepting-speech sequence,
IDs, and causal links with at least two listeners.

### N-02 — The tests need explicit boundary-report and migration-edge oracles

**Location:** Protocol §§5.3, 11.3, 13, especially WAP-03/09/15/16.

**Problem.** The acceptance list captures major properties, but does not
explicitly check a complete `BoundaryDelivery.reports` construction or
guarantee coverage of individual migration branches. The P2 seed matrix is
a trajectory regression, not an action/failure/interrupt coverage assertion.

**Concrete counterexamples.**

- An implementation could deliver a heard utterance and preserve action
  progress, passing the assertions written in WAP-03, while omitting its
  `utterance_heard` report or setting `addressed` incorrectly. The harness
  would then offer the wrong turns even though the utterance content arrived.
- Successful P2 trajectories with the pinned equal speech/wait durations do
  not test a different-duration profile. A trajectory that never attempts an
  over-cap reply does not establish its failure mapping. This review does not
  assert that every such edge is absent from all P2 runs; the specification
  simply supplies no coverage guarantee.

**Recommended fix.** Add a report-construction oracle covering every report
kind, subject ID, nullable field, initial-boundary behavior, multiplicity,
ordering, and the relationship to transient feedback. Explicitly retain the
predecessor's current-boundary-only feedback and exactly-once delivery rules.
Keep report construction separate from the decision-loop's notification
classes and mute choices.

Retain the P2 projections and add committed scripted migration fixtures for
the cases in B-04–B-06. Do not rely on random seeds to exercise them.
WAP-14 should also clarify that its “needs, position and inventory only”
wording describes sensory suppression, without contradicting §5.1's retained
static explored terrain and mandatory metadata.

**Missing test.** A mixed boundary containing action completion, addressed
and overheard speech, a need-band change, a first sighting/cue upgrade, a
progress step, and waking should have an exact expected report array.
Save before acknowledgement, restore, deliver once, and verify that the next
boundary does not repeat consumed feedback. Separate fixtures should pin the
migration edges instead of merely increasing seed count.

**PR-D3 and the memory-off arm.** Section 5.2 explicitly says that the world
shows the same material identity, apparent descriptors, and physical tells
regardless of experience. Recognition lives in memory and is lost at the
memory-off period boundary. It forbids a world-side familiarity counter.
Nothing in that mechanism requires the world to record “who knows what.”

The true material/archetype IDs and instance tells are part of the recorded
Owner decision; this review does not reopen them. The accepted persistent
exposure receipts must not be reclassified as learned knowledge merely
because they record earlier physical exposure. They are backend-private and
expressly retained by ADR 0007 D3.

WAP-17 tests equal physical presentations, but it does not alone test the
cross-period reset. Add an integration fixture in the named memory/decision
successors: both arms learn a distinctive false-appearance lesson; after
the shared period boundary the off-arm context has no lesson, previous
dialogue, or mechanical commitment content, while its current physical
perception and explored static map remain intact. Include a short nap that
does not end a period. This tests the accepted policy without selecting K
or requiring the world to know it.

The specification is therefore **not yet a guess-free implementation
contract for M12**, even when legitimate successor-spec dependencies are
acknowledged.

### 4.5 Migration assessment

The compatibility pack cannot currently be certified as preserving the
advertised per-tick v1 projection. B-04 is an information/timing mismatch,
B-05 is a missing policy-visible composite failure, and B-06 contains an
explicit terminal-origin contradiction and incomplete mapping oracles.

Keep the archived v1 fixtures, seed set, separate random-stream requirements,
and owner-approved removal/viewer plan. Fix the compatibility contract
before generating “passing” v2 expectations from an implementation; otherwise
the implementation would silently choose the missing semantics.

### 4.6 Responsibility boundaries

The spec does not embed a crafting recipe or a rule-library implementation.
Its Owner-approved sleep validation bounds and citations of frozen v1 values
are not grounds to reopen content choices.

| Responsibility | Proper owner / review treatment |
|---|---|
| Vocabulary members, tells, phenomenon comparison, attempt descriptor representation, conservation | Rule-representation; the protocol must preserve their filtering/interface obligations |
