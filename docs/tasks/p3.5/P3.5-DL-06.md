### Goal and scope

Establish whether the pinned live provider accepts the single-copy schema and parses the approved sample at least as often as P3. This is the first of the two paid operations. It measures the cost input to the live-run decision.

**Allowed files and forbidden dependencies.** Write `sim/v2/harness/provider_check.py` under `backend/src/living_island/`, `backend/tests/v2/provider_check/**` and `docs/tasks/p3.5/M14-provider-check.md`. Regenerate this stage's rows in the EV-04 ledger during its exclusive writer slot. Consume the DL-01 adapter. Use `.env` only at approved live runtime. Raw call artifacts stay in the ignored run directory. The card may update its own handoff. The shared-file allocation and M13 exclusions in [M14 plan §3](M14-plan.md#3-file-ownership) apply.

### Deliverables

- A repeatable offline preflight with the adapter's actual provider-framed bytes, exact vocabulary/schema/prompt hashes, dated model resolution, window/reserve, counter and peak CNY price evidence. Verify documented schema restrictions, the absence of tools/second schema copy, key redaction and the preserved reasoning channel on fake responses.
- Before dispatch, pin the unmodified fixture hashes, sample count and success rule in `M14-provider-check.md` and link the owner's disposition of OQ-P3.5-M14-2. Use the approved six-kind sample, one prepared input per kind from EV-05. Score each dispatch including invalid outputs, and publish decision-only and all-kinds counts. Use the final CR-008 P3 smoke (22/22 parsed, zero local rejections) as the historical comparator. Report sample size and uncertainty. Do not pay to rerun P3.
- Project the check using the fake wire sizes, pinned worst-case rates and permitted attempts, reconciled opening balance and concurrent liabilities. Run the bounded check once if authorized. Archive records and hashes, transport outcomes, adoption/parse numerators and denominators, usage, actual CNY per dispatched attempt and per logical call, by kind when observed. Feed the phase ledger and day-sizing table.

### Acceptance

- Fake and paid paths use the same production adapter and schema field. Rebuild sent bytes for every check attempt without network or credentials. Show one schema on the wire and no private reasoning in the next input. Missing required wire support, changed model mapping or insufficient budget blocks dispatch.
- Confirm provider acceptance and typed parsing for the predeclared sample. Compare like-for-like decision parse results with M9 and publish the other four call kinds separately. Unexpected output, a retry or a failed dispatch stays visible in the denominator and ledger. An incomplete or failed check withholds step 2. If the single-copy form fails, report the incompatibility for an owner change request before considering tool calling.
- The cost/day forecast uses the live rates and all sample costs, including failed/paid attempts, with EV-05's per-kind calls/day and growing contexts. A missing usable measurement blocks the estimate or uses a documented conservative bound. Report actual measured figures separately from reservations.
