## Findings

### B1 (blocking): process progress reports miss changes from legal rule effects

`processes.py:38–47` (`contribute`) records progress only when phase 2 awards a
contribution. `reports.py:59–66` (`build_reports`) derives the opening and closing
word solely from those contributions. RR §§2.2 and 3.4 permit an ordinary world
rule to set `process.work_done` after phase 2, and WAP §5.3 requires a report when
the descriptor of a process the resident contributes to changes in the tick.

`test_review_process_world_effect_changes_progress` fails on the exact tip. Start
`inst_e` at zero of four work units with a usable input. A contributes one unit
(`started`) and a legal `every:1` world rule sets `process.work_done` to two.
The objective state-change event and the running packet both show the effect,
and the packet displays `halfway`. Its report array is empty, so the harness
receives no progress notification for the actual change.

Requested fix. Use one per-process tracker for the opening work and the last
committed work value, including `set_state` changes after phase 2. Keep the
contributor IDs for the report audience. Retain the last value before removal
when the process settles under the documented final-change assumption. Reuse
the existing descriptor formula and ignore effects from refused branches. Add
the failing real-boundary vector, with an exact `progress_step` for A and a
noncontributor control. Keep the existing multi-contributor and settlement
cases green.

### B2 (blocking): the EN-06 follow-up misses a dead-listener regression

`test_packets.py:635–648` sets up a dead in-range bystander and checks that C has
no packet. `perception.py:324–330` already suppresses all dead residents' packets.
Removing only `listener.alive` from `speech.py:159–163` therefore leaves all
23 EN-05 packet tests green while emitting a false `utterance_heard` for C.
Removing the range check does fail the committed test at D's packet assertion.

Requested fix. Keep the real-packet checks and also compare the objective
`utterance_heard` listener IDs for the utterance with exactly `[B]`. The
independent `test_review_dead_bystander_has_no_hearing_event` passes on the
reviewed source and fails with `['res_b', 'res_c']` when the filter is removed.
The change belongs in the EN-05 test, and the speech filter already behaves
correctly.

### B3 (blocking): EN-26 needs the objective binding in the same scenario

`test_packets.py:782–819` discards the start tick result and compares the actor's
packet with the watcher's packet. EN-26 also requires `act_items` to agree on the
original IDs and quantities for the same held uses. Earlier settlement tests
check objective slot payloads in separate scenarios. A disagreement between
the watcher/actor pair and the objective event in this by-kind case has no
assertion here.

Requested fix. Keep the start tick result in the existing test. Compare the
event's `(role, entity_id, quantity)` per relevant slot part with the corresponding
watcher-start entries and the actor's later `items_used`. Keep the held-output
and consumed-input assertions. I added that comparison in scratch and it passed
on the reviewed implementation (`C:/Temp/li-41d909f4b6cc`).

## Open questions and recommendations

- **OQ-P3.5-EN-05, container visibility.** Keep the provisional open-process
  workspace projection and descriptor-only ordinary containers and stores.
  `test_process_progress_and_container_visibility` checks the positive and
  negative entity exposures. The policy is contained in `observe.sight_place`
  and leaves physical holdings, reach, and effects alone. Keep the OQ open for
  the owner, including the consequence that visible contents of an open process
  can receive ordinary exposure receipts independently of watching.
- **OQ-P3.5-EN-05, final progress.** Keep the provisional rule that a genuine word
  change can be reported on the same boundary as settlement or a stop. The
  mixed dawn test, process test and early-wake probe reach it. Removing the
  running view generates no separate change. This retains the last actual work
  change and leaves the three fixed progress bands intact. Resolve B1 without
  broadening the notification to mere watchers. Keep the OQ open for the owner.
- **CR-P3.5-EN-05, WAP-19.** Recommend the proposed acceptance-only change under
  runbook §6.1. A `woke` report comes from natural sleep completion, early waking
  or the expiry of unconsciousness. In each path speech settles before phase 6
  and the recipient was asleep or unconscious for the hearing sample. A sleep
  that starts and wakes in that tick enters sleep in phase 2 before emission as
  well. Protocol §§5.1 and 6.3 and engine §§9.4–9.6 exclude hearing in each case,
  including the compatibility sleep-sight flag. Thus the frozen world can
  produce speech and wake reports for different residents at the same boundary,
  but cannot deliver both to one resident. The awake mixed-array and wake-array
  split preserves the frozen runtime rules and report order. For exact coverage
  of the reachable overlap, extend an early-wake row to assert the full array
  including `progress_step` before `woke`, and annotate the split in the tests.
  The CR stays proposed, awaiting owner. Rework can proceed under the split.
