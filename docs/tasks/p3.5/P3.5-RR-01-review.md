- Hashes (§1): `content_hash` excludes provenance; `rule_library_hash` covers
  the active rules sorted by ID with provenance; entries are sorted by ID after
  composition, so file order does not change the hash (RR-01).
- Provenance (§5.9): file rules are `{kind:"authored", pack_id}`; a proposal
  is validated against a copy and does not enter the active library (RR-22).

  `DUPLICATE_ID`); instances and sources cannot be replaced; `disable` must
  name a base rule (RR-30).

  controls (RR-03); closed registries refuse unknown components, condition
  kinds, effects and triggers (RR-25).
- Unreachable checks (§7, RR-29, RR-34): a pair is reported only with a start
  implication and a completion invariant. The completion invariant is
  certified only for terrain checks of a verb whose actor is asleep (a
  stationary sleeper; terrain has no effect that changes it, §3.4). Everything
  else is omitted, which is the conservative reading the spec asks for. No
  content names are hard-coded.
- The v1 import found before review (`world.content.canonical_json_bytes`) is
  replaced by a v2-local encoder that reproduces the published vocabulary hash.

## Findings

### N1 (non-blocking, owner decision): reversible format defaults

OQ-P3.5-RR-01 records choices that P3.5-CT-01 and P3.5-CT-02 will build on:
`${name}` placeholders with a typed binding table, sibling directories for
`extends`, hyphenated pack IDs (`compat-v1`, `starter-v1`, `engine-test`)
outside the member ID grammar, the composed pack hash envelope, numeric
descriptor defaults, dropping offsets of disabled periodic rules, and
diagnostic precedence. None contradicts a frozen spec. Recommendation: the
owner confirms them as written, so the content cards do not reopen them.

**Owner decision (2026-11-20):** confirmed as written. P3.5-CT-01 and
P3.5-CT-02 build on these defaults.

### N2 (non-blocking): v2 tests must not import v2 code at collection time

The frozen v1 registration check inspects the loaded `living_island`
modules, so a v2 module imported during pytest collection can fail v1
registration tests. RR-01 imports its loader inside test functions. P3.5-PR-04
imports `world.v2.protocol` at module level and still passes, so the effect
depends on which modules are loaded. Recommendation: add one line to the M12
plan rules (§6) so every later card keeps v2 imports out of collection or
runs the registration tests in the same session as its own tests.

**Done (2026-11-20):** added to M12 plan §6.
