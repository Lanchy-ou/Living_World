# P3.5 retrospective and next direction

Author: Claude Code. Date: 2026-11-28. This is a working record and a
recommendation, not an owner decision. The signed facts are in the
[P3.5 closeout](P3.5-closeout.md) and the milestone Gate 3 records.

## 1. What happened

P3.5 ran from 2026-11-15 to 2026-11-26. It had 47 task cards and pull
requests #5 to #72 ([card index](P3.5-card-index.md)). Paid model calls
settled CNY 6.40381186 under the CNY 20 phase cap.

| Period | Work | Roles |
| --- | --- | --- |
| 11-15 to 11-19 | M11: eight ADRs, CR-009 to CR-011, eight frozen specs | Drafted under the owner's direction, rechecked by independent reviewers, decided by the owner |
| 11-19 to 11-23 | M12: v2 engine, protocol, `compat-v1` equivalence | Claude Code orchestrated waves of Codex executors |
| 11-23 to 11-26 | M13 starter world, M14 live resident, EV-07 | Codex executed cards except EV-07 rounds 2 and 3; Claude Code did Gate 2, acceptance, pushes and merges; the owner signed |

The working mode changed on 2026-11-23. Codex executors (`gpt-6.2-sol`,
high effort) write card code. The exception is EV-07 rounds 2 and 3, which
Claude Code wrote under owner scope A. Claude Code never reviews its own
writing; an independent Codex reviewer checked EV-07 and the closeout.

## 2. What worked

- **Frozen specs and change requests.** Every gap went to
  `open-questions.md` with options and a recommendation, and the owner
  ruled on it. No rule or number was invented in code.
- **Equivalence before novelty.** M12 proved the v2 engine against the v1
  archive. M14 could then run in `compat-v1` without waiting for M13.
- **Writer and reviewer kept apart.** Independent reviews caught real
  defects late in the phase. Examples are the EV-07 gap at parent package
  initializers and a wrong "not run" claim in the closeout draft.
- **Paid-run discipline.** Release windows, a spend ledger, peak-tariff
  reserves and a runtime stop guard kept every paid run inside the cap.
  Replay of every live run needed zero model calls.

## 3. What went wrong, and the lessons

1. **A claim made before reading the case settings.** The four-day M14
   horizon assumed that a faint would end a waking period. `compat-v1`
   disables mental fatigue, so no faint can happen. One paid run ended in
   starvation at tick 442 without the expected consolidation. *Lesson:
   read the case configuration before predicting world behavior.*
2. **Counting by text search.** A regex over audit facts gave 215 skill
   citations. Copies were counted twice; the adopted binding receipts give
   72. *Lesson: count from the receipt the system writes for each adopted
   act.*
3. **A model-facing schema looser than its contract.** `about_tick` was
   optional in the change-set schema but required by the contract, so
   valid-looking operations were dropped. *Lesson: the schema the model
   sees must encode every contract requirement, with one typed record per
   kind.*
4. **Prompt changes break fixture hashes.** Prompt edits changed recorded
   fixture hashes and failed CI. *Lesson: regenerate dependent fixtures in
   the same change as the prompt.*
5. **Rework friction.** The owner found the repeated EV-06 rework rounds
   tiring. The single-writer rule means each fix returns to the executor.
   *Lesson: collect all findings of a review round into one instruction,
   and check the whole chain offline before any paid step.*
6. **An option described more broadly than it was done.** In the owner
   conversation, EV-07 option A was first described as removing the
   launchers, which it did not do. The repository records only the
   delivered scope.
   *Lesson: state exactly what an option changes before the owner
   chooses.*
7. **Environment details.** CI runs only for branches with an open pull
   request. Folders created by another account need command-scope
   `safe.directory`. Python text writes on Windows produce CRLF. Release
   windows must sit inside one tariff period.

## 4. What the evidence shows

**Shown.** The v2 engine matches the v1 archive on the approved seed set. Each starter mechanic works, and a
rule-based week runs in 357 s against a 1,800 s budget. One live resident
completes four game days with consolidation, morning selection and valid
memory citations, and replays offline.

**Not shown.** Nothing yet shows that memory improves behavior. The M14
evidence is thin:

- Consolidation wrote two records in four days. The episode was never
  cited.
- The skill was cited in 72 turns, but its practice counters stayed at
  zero. A citation shows that the model read the record, not that the
  record changed what it did.
- Ella ate four fruit in four days. The earlier tick-442 capture
  ended in starvation.
- The sent input ranged from 3,714 to 175,794 tokens across the run. With five residents and speech, the context will grow faster.
  That affects both cost and decision quality.

**Cost.** Ella's four live days settled CNY 2.16607564, about CNY 0.54
per resident-day. That is far below the plan's CNY 4 estimate. The M15
matrix of 210 resident-days would then cost roughly CNY 114 at the same
rate. Multi-resident speech and longer contexts will raise this, and the
worst-case reserves are several times higher.

## 5. Recommended next direction

The question for the next phase is whether memory makes a resident behave
better. Answer it cheaply before paying for the M15 matrix.

1. **Fix the M14 findings offline (no spend).**
   - Make skill practice counters match explicit-target attempts, so a
     cited skill can gain or lose evidence.
   - Decide how consolidation should treat operations whose witness keys
     were not observed, rather than dropping them silently.
   - Improve food finding through the sent map and perception text, not
     by changing world rules.
   - Bound the waking-period context, or show that the growth is
     acceptable at five residents.
   Verify each fix with the fake model and replay.
2. **Run a small paid pilot (owner release).** Five residents for one
   game day, memory on and memory off, one seed. That measures real
   multi-resident cost and context growth, and gives a first look at the
   memory difference.
3. **Size and decide M15.** Use the pilot's measured costs to size the
   plan §4.1 matrix and propose a budget. The owner decides whether to run
   it.
4. **In parallel, with no spend:** the v1 removal cleanup listed in
   [OQ-P3.5-EV07-1](../../spec/open-questions.md#oq-p35-ev07-1-scope-of-the-v1-retirement),
   and removal of finished worktrees with the owner's per-item approval.

Keep the working mode: Codex executes, Claude Code reviews, the owner
decides. Add one check before every paid step: case settings read, tariff
window confirmed, schema matched to contract, full chain passed offline.
