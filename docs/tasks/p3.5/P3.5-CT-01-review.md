## Findings

### B1 (blocking): the scan crashes on the compatibility pack

`authored_ids` in `test_recipe_free.py` reads each pack's `rules.toml` and
`instances.toml` as literal arrays of rows. P3.5-CT-02's `compat-v1` binds
both sections whole (`rule = "${rules}"`, `instance = "${instances}"`), which
the confirmed OQ-P3.5-RR-01 format allows. With both branches merged,
`test_ct14_synthetic_ids_are_disjoint_from_real_ids` and
`test_en22_world_v2_is_recipe_free` fail with
`TypeError: string indices must be integers` at line 21.

The scan would also miss the compatibility rule IDs, which live in
`rule-templates.toml` (see the P3.5-CT-02 review, B1).

Requested fix:

- Read every `*.toml` file of each pack directory, except `pack.toml` and
  `compat-codes.toml`. Collect `id` from the `rule`, `archetype`, `material`
  and `instance` sections, whether the section is an array of tables or one
  table. Skip a section whose value is a placeholder string.
- Add a planted case for a placeholder section and one for a second rule
  file, so the scan is tested on both shapes.
- Rebase on main after P3.5-CT-02 merges, and run the scan against the real
  `compat-v1`. Its rule IDs (`compat_gather_fruit` and the others) must be
  in the scanned set.
