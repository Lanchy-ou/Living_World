## Findings

### B1 (blocking): `TARGET_GONE` is raised in phase 2 instead of phase 6

`processes.contribute` sets `action.pending_stop = "TARGET_GONE"` when the
process is missing or out of reach, so the contribute finishes in phase 3 as a
member of the completion set.

The specs place this stop in phase 6, outside the completion set:

- Engine §10.1 table: `TARGET_GONE` is detected in phase 6, ends at `t+1`,
  and is **not** in a completion set. Only `EXHAUSTED` at progress and
  `PATH_BLOCKED` are phase 2 stops.
- Engine §7.3: out-of-reach contributions get the target-gone stop at phase 6.
- Engine §7.2 only says that no unit is added while the process is missing or
  out of reach.
- `stops.py` (P3.5-EN-04) already detects this case in phase 6 with the
  §10.1 priority.

Consequences:

- An extra member joins the completion set, so the resolution shuffle draws
  once more. Every later RNG draw shifts, and PR-07 compares this order
  with v1.
- A death in phase 5 of the same tick should stop the action with `DEATH`,
  the higher priority. With the phase 2 stop, `TARGET_GONE` wins.

`test_process_stops_in_phase2_when_an_earlier_actor_moves_it` asserts the
wrong timing.

Requested fix:

- In phase 2, a missing or out-of-reach process adds no unit and sets no
  stop. Phase 6 (`stops.py`) ends the action.
- Rewrite that test to expect the phase 6 stop. Add two checks:
  - the contribute is not in the completion set: the resolution RNG state
    equals a control run without it;
  - a same-tick death gives `DEATH`, not `TARGET_GONE`.
- `contribute` then needs the process only to count work. Keep the
  `entities.get` lookup, because the process can be gone; the case is
  reachable and tested.

### B2 (blocking): guards with no test

Each of these must have a test that reaches it, or be removed (AGENTS.md
boundary rule):

1. `finish_processes`: `state.entities.get(key)` returning `None`, so the
   subject is skipped. §7.3 requires skipping deleted subjects, so the guard is
   right, but no test deletes an open process before its 4b turn. Example: a
   lower-ID process completion that consumes another open process as an
   input.
2. `world_rules.run`: the same `None` skip in 4a. A subject can only be
   deleted by an earlier application in the same rule's turn. Show that case
   with a test, or remove the guard.
3. `finishes_with`: `action.pending_failure is None`. A contribute that
   failed at start stays active until `t + invalid_attempt_ticks`. With
   `invalid_attempt_ticks = 1`, as in the engine-test pack, it has already
   settled in phase 3. With 2, it can sit in reach of a process that
   completes. Add a test with `invalid_attempt_ticks = 2` in the processes
   conftest, or remove the condition.

### B3 (blocking) — Phase 6 replaces a fixed contribution start failure

`backend/src/living_island/world/v2/engine/stops.py:34` checks every
`Contribute` command for a missing or distant target. That includes an
invalid timed attempt whose failure was fixed by `tick.py:358`. Engine §4.1
and WAP §4.2 require the start failure to be delivered at
`t + invalid_attempt_ticks`. The WAP target-gone exception applies to a
running contribution without a fixed completion.

Strengthen `test_pending_contribution_failure_cannot_succeed_on_closure`
in `backend/tests/v2/engine/processes/test_world_rules.py:575`. At tick 1
only B's move should finish. A's attempted contribution should still carry
`OUT_OF_REACH`, then finish once at tick 2 with that failure code. The
strengthened test failed on `6403063` because A stopped at tick 1 with
`TARGET_GONE`. Restrict the phase 6 target-gone check to a `Contribute`
with `action.pending_failure is None`. With that single change in scratch,
the regression and all 26 process tests passed. Record the minimal edit to
merged EN-04's `stops.py` in the next handoff under runbook §5.
