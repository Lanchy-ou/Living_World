## Handoff

### What changed

- The world snapshot encodes the full committed state, including pending
  deliveries, deferred feedback, receipts, phase looks, proposals, agreements,
  the event cursor, RNG and allocator history. The tick-zero event hashes those
  same bytes. Restore rebuilds the rule schedule from the pinned starting
  content and the saved additions, then returns the saved packets as built.
- The run manifest pins WAP 0.1, the vocabulary, the starting library and the
  base-first pack hashes. The packet journal writes immutable batches by observed
  boundary, including no-turn boundaries. Re-ingestion must match the saved
  bytes before acknowledgement. One checkpoint publishes the world, committed
  journal prefix and opaque coordinator state together.
- Recorded boundaries write approved normalized rules to
  `rules/<content_hash>.json` before emitting `rule_added`. Replay loads
  those files from the recorded events and checks their canonical bytes and
  digests. It runs recorded `TurnSubmission`s through the world, verifies the
  packet journal and objective event bytes, and yields the full regenerated
  snapshot per boundary.

| Acceptance | Evidence |
|---|---|
| EN-20, RR-22 | An added rule is available at the start boundary, while an in-flight gather keeps its earlier rule. The test checks the manifest and snapshot hashes, the stored rule before event emission, atomic retry and missing or altered content refusal. |
| EN-21, WAP-16 | Two executions from each of tick zero and a later snapshot match all event and snapshot bytes through refill and verb/world-rule additions. The proposal tests restore before the first reply and reject a second reply after accept or refuse. |
| EN-29 | Restoring after acknowledged tool-start observation and tool disappearance preserves the captured look. A consumed allocated ID still collides after restore, and exhausted allocation leaves the entire boundary unchanged. |
| WAP-05, WAP-19, Round 3 watch | Restore wraps the EN-05 production scenarios before each acknowledgement. The journal matches packet bytes and report order, the cancelled gather arrives once, and the watcher still receives no exposure for the consumed input or the occluded target. |
| WAP-11, RR-23 | Snapshot vocabulary, library and pack mismatches are refused. Adding a rule preserves the schema hash and changing the enabled verb set changes it. |

### Deviations

- The serial card used `world/v2/engine/state.py` for snapshot decoding of
  dialogue keys and ordered rule history, the effective pack pin and integer
  component data. It used `world/v2/engine/tick.py` for committed packet access,
  the canonical tick-zero hash and the pre-event rule storage hook.
- `world/v2/rules/loader.py` and `world/v2/rules/rule.py` needed a narrow
  canonical-input path under runbook §§5 and 6.1. A normalized world or
  process rule has an empty instrument list. The authored rule grammar
  forbids that field. Restore and replay now read the canonical form while
  authored and proposed inputs keep the frozen grammar.
- Persistence tests reuse the existing EN-05 scenarios and fixture factories
  as written. The adapter saves and restores a second world before each
  acknowledgement, compares complete states and packet bytes, and then runs
  the original scenario assertions.
- The first full attempt found a pytest module name collision with the v1
  persistence tests. The new test module now has a unique name. The
  preliminary combined attempt began before the new sources were committed
  and hit `ACTIVE_IMPLEMENTATION_SOURCE_DRIFT` in ten registration tests.
  The final checks used the clean, rebased implementation commit.
