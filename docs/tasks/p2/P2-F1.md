## Brief

```text

  alongside (P2-F0 folded in by plan Amendment 2)
Spec baseline (commit SHA): main @ 5bb89c2 (P2-00..P2-03 merged; plan Amendment 1; P2-F0 card)
Goal / non-goals:
  Goal: P2 plan §2 P2-F1 as amended on 2026-11-11. Turn the existing offline replay viewer
  into a map-first, warm top-down pixel-art view of the island, and write the design spec
  that P2-F0 would have written, describing what was built:
  - the island map is the dominant part of the interface;
  - free zoom, drag-to-pan and a "view entire island" control;
  - a small amount of global information (day and time, living residents, resource
    summaries that the replay carries);
  - clicking a resident opens a detail panel (current action, condition values, inventory);
    selecting never moves the camera and never pauses playback;
  - events, resources and debugging detail stay available on demand;
  - replay loading, playback, seeking, speeds, filters and error handling are preserved.

  - any change to backend/, contract/, generated files, ReplayBundle or DisplayFrame;
  - any world rule, legality check, physiology or resource computation in the frontend;
  - features that need data the replay does not carry (personality, goals, memory,
    perception overlays, relationships, LLM traces, god controls, live view, narrative);
  - alternative style proposals or a separate style approval before implementation;
  - committing or downloading third-party assets (none is used).
Lane / depends on: after P2-03. The only active task; the Gate 2 reviewer takes the second
  slot.

  frontend/** except frontend/src/api/generated/;

  docs/design/** (new, optional);

  it supersedes.
  Third-party assets: none is committed or downloaded without the owner's approval in chat.
  Project-made assets record how they were made.
Deliverables:
  1. The viewer: renderer, assets, layout, panels and controls as described in the goal.
  2. docs/spec/frontend-design-v0.1.md: visual direction and departures from the concept
     image, asset interface (tile size, scaling, layer order, facing and animation
     conventions, naming, formats, license record), layout and interaction, data mapping
     from every displayed element to a ReplayBundle / DisplayFrame / event field, the change
     set against p1-replay-frontend-v0.1.md (FE-01..FE-04, §4, §6, FE-T01..FE-T13), and
     numbered acceptance checks.
  3. docs/adr/0005-frontend-rendering.md: the rendering approach.
  4. Automated tests for the acceptance checks that can be automated.
  5. Validation on real replays: zoom and pan, shared-tile residents, night, death and
     dropped items, and playback of a 1,009-frame rule-based default-island replay at
     16 ticks per second.
Acceptance (positive, negative, edge, determinism):
  - Every displayed element maps to an existing contract field or is a stated pure display
    derivation of recorded frames and events.
  - Nothing in the frontend computes legality, physiology, resources or outcomes

  - Motion interpolation, facing and effects are presentation-only: they are pure functions

  - No file outside the allowed list changes; type generation leaves no diff.
```
