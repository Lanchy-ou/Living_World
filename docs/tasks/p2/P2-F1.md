# Task P2-F1: Frontend implementation with its design spec (P2-F0 folded in)

## Brief

```text
Task ID / title: P2-F1 — Pixel-art replay viewer, with the frontend design spec written
  alongside (P2-F0 folded in by plan Amendment 2)
Spec baseline (commit SHA): main @ 5bb89c2 (P2-00..P2-03 merged; plan Amendment 1; P2-F0 card)
Goal / non-goals:
  Goal: P2 plan §2 P2-F1 as amended on 2026-11-11. Turn the existing offline replay viewer
  into a map-first, warm top-down pixel-art view of the island, and write the design spec
  that P2-F0 would have written, describing what was built:
  - the island map is the dominant part of the interface;
  - free zoom, drag-to-pan and a "view entire island" control;
  - a small amount of global information (day and time, living residents, resource
    summaries that the replay carries);
  - clicking a resident opens a detail panel (current action, condition values, inventory);
    selecting never moves the camera and never pauses playback;
  - events, resources and debugging detail stay available on demand;
  - replay loading, playback, seeking, speeds, filters and error handling are preserved.

  - any change to backend/, contract/, generated files, ReplayBundle or DisplayFrame;
  - any world rule, legality check, physiology or resource computation in the frontend;
  - features that need data the replay does not carry (personality, goals, memory,
    perception overlays, relationships, LLM traces, god controls, live view, narrative);
  - alternative style proposals or a separate style approval before implementation;
  - committing or downloading third-party assets (none is used).
Lane / depends on: after P2-03. The only active task; the Gate 2 reviewer takes the second
  slot.
Allowed files / forbidden dependencies:
  frontend/** except frontend/src/api/generated/;

  docs/design/** (new, optional);

  it supersedes.
  Third-party assets: none is committed or downloaded without the owner's approval in chat.
  Project-made assets record how they were made.
Deliverables:
  1. The viewer: renderer, assets, layout, panels and controls as described in the goal.
  2. docs/spec/frontend-design-v0.1.md: visual direction and departures from the concept
     image, asset interface (tile size, scaling, layer order, facing and animation
     conventions, naming, formats, license record), layout and interaction, data mapping
     from every displayed element to a ReplayBundle / DisplayFrame / event field, the change
     set against p1-replay-frontend-v0.1.md (FE-01..FE-04, §4, §6, FE-T01..FE-T13), and
     numbered acceptance checks.

  4. Automated tests for the acceptance checks that can be automated.
  5. Validation on real replays: zoom and pan, shared-tile residents, night, death and

Acceptance (positive, negative, edge, determinism):
  - Every displayed element maps to an existing contract field or is a stated pure display
    derivation of recorded frames and events.
  - Nothing in the frontend computes legality, physiology, resources or outcomes
    (AGENTS.md principle 6; p1-replay-frontend FE-03).
  - Motion interpolation, facing and effects are presentation-only: they are pure functions
    of recorded frames and events, are never written back, and at rest every entity is
    drawn on its recorded tile.
  - Selecting a resident changes neither the camera nor the playing state.
  - All map drawing is data-driven: a different map, resident count or stock draws without
    code changes; the concept image is not reproduced as a fixed map.
  - The P1 fixtures and the shared backend fixtures still load; invalid files are still
    refused and never repaired.
  - Drawing is deterministic: the same bundle, tick and view give the same output.
  - Colour is never the only cue; residents have a letter as well as a look.
  - No file outside the allowed list changes; type generation leaves no diff.

Open risks / deferred decisions:

  - Data gaps found while building become OQs for P3 or later; no contract change is
    proposed in P2.
  - If M6 changes the map, the viewer must still work with no change.
```

## Owner authorization (2026-11-11, in chat)

The project owner gave this instruction when starting the task. It is the source of plan
Amendment 2 and of the scope above.

> Implement the frontend directly. Do not produce alternative design proposals or wait for
> another style approval. Make reasonable implementation decisions and deliver a working
> version for me to review.
>
> [...] Record my authorization to replace the separate design-approval step with direct
> implementation and document design decisions alongside the work. Follow the repository's
> branch, worktree, testing, independent review, and handoff requirements.

Creative freedom, as granted in the same message (summarized; the wording is the owner's
where quoted):

- The visual direction and the concept image are "starting points, not a fixed
  specification". A stronger design may be implemented "directly without requesting another
  style approval", including departures in art style, proportions, palette, layout and
  presentation.
- The core experience must be preserved: "observing a living island, freely zooming and
  panning, seeing concise global information, and clicking residents to inspect their
  details".
- Significant departures are documented briefly with the reason.
- The freedom covers visual design and presentation only. It "does not authorize changes to
  world rules, frozen data contracts, backend behavior, or repository safety requirements".

Visual direction given by the owner: warm top-down 2D pixel art; friendly residents with
moderately enlarged heads and recognizable bodies and limbs; the three residents told apart
by hairstyle, clothing colour and silhouette, with letter labels as a supplement; restrained
terrain textures; clean interface typography. The side-by-side overview and close-up in the
concept image are comparison views, not a required split screen.

Effect on the process:

- Gate 3 (MF) is not skipped. It moves to the end of this task: the owner reviews the
  working viewer.
- Gate 1 (executor checks) and Gate 2 (independent reviewer) apply unchanged.
- The owner's concept image ("A — Warm Pixel Art") is a style reference only. It is not
  committed, because its source and license are not recorded.
